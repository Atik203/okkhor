# 0.3 core contracts (normative)

- Status: Binding for the 0.3 multi-agent sprint (see ADR 0010).
- Owner: Task A (architect). Implementations are owned by Tasks 1–3.
- Scope: public contracts only. **No implementation code, no legacy binaries, no
  proprietary assets, no real user text, and no secrets are part of this
  contract.**
- Companion decisions: ADR 0001 (crate boundaries), ADR 0005 (legacy FFI), ADR
  0008 (benchmark harness), ADR 0010 (these contracts).

This document is the single source of truth for the three 0.3 module crates.
Where it conflicts with a task description, this document wins; escalate rather
than silently widening scope.

## 1. Non-negotiable invariants

1. **Dependency direction is one-way.** Each of the three crates depends only
   on the existing `okkhor-core`. There are **no** cross-dependencies:
   `okkhor-lang` ↛ `okkhor-transliterate`, `okkhor-transliterate` ↛
   `okkhor-lang`, and neither depends on `okkhor-compat`. The daemon composes
   them.
2. **No changes to `okkhor-core`** in this sprint. Shared types (`Language`,
   `Candidate`, `CandidateSource`, `SuggestionRequest`, `normalize_nfc`,
   `normalize_lookup`, `contains_bengali`) are consumed as-is. A type that must
   be shared by two new crates is a design smell: define it locally or propose
   a core change via a new ADR and the lead.
3. **Windows-first, but pure logic stays portable.** `okkhor-lang` and
   `okkhor-transliterate` carry `#![forbid(unsafe_code)]` and run in CI on any
   target. `okkhor-compat` confines all `unsafe` to its private `ffi` module on
   `cfg(windows)`. Every `unsafe` block needs a `// SAFETY:` comment naming the
   invariant, per AGENTS.md.
4. **Typing path stays clean.** No crate in this contract performs I/O, FFI,
   network calls, logging of text, or unbounded allocation from the hook
   callback. Construction/import/load happens once at daemon startup; runtime
   calls are bounded lookups on the input worker.
5. **Privacy by construction.** Public error `Display` text must never contain
   user text, fixture contents, full paths, window titles, or proprietary
   asset bytes. Errors expose a stable `kind()` and optional numeric `code()`
   for the daemon's allowlisted logger.
6. **Fixtures are synthetic only.** All test data is authored JSON committed
   under each crate's `tests/fixtures/synthetic/`. No legacy files, no binary
   blobs, no `settings.pkl`, no executed legacy application.
7. **Skeleton honesty.** Unfinished behavior is marked `scaffold` or `TODO`
   with owner Task 1/2/3 and roadmap milestone; no placeholder may look
   finished.

## 2. Shared conventions for all three crates

### 2.1 Workspace and manifest conventions

Match the existing workspace (`Cargo.toml`: edition 2024, rust-version 1.85,
`version.workspace = true`, `[lints] workspace = true`). Reuse declared
workspace dependencies: `okkhor-core`, `serde`, `serde_json`, `thiserror`.
`okkhor-compat` may additionally declare `windows = "0.62.2"` under
`[target.'cfg(windows)'.dependencies]` with the minimal features it needs
(`Win32_Foundation`, `Win32_System_LibraryLoader`), the same pinned version as
`okkhor-win`. Hoisting that pin into `[workspace.dependencies]` is a lead
decision, not a task-agent edit.

Each agent may add exactly one workspace-member line to root `Cargo.toml`
(`"crates/okkhor-lang"`, `"crates/okkhor-transliterate"`,
`"crates/okkhor-compat"`). All other shared files are lead-owned.

### 2.2 Type and serde conventions

- Derive `Debug` on every public type. Data types additionally derive
  `Clone, PartialEq, Eq` (and `Serialize, Deserialize` when serializable).
  Floating-point fields derive `PartialEq` only.
- serde enums use `#[serde(rename_all = "snake_case")]`, matching
  `okkhor_core::Language` and `CandidateSource`. Stable string codes are part
  of the contract; add `as_str()`/`from_code()` rather than relying on `Debug`.
- **Fixture language strings are `"bangla"` and `"english"`, never `"bn"` or
  `"en"`.** `okkhor_core::Language` has no serde aliases: serde matches the
  variant names `Bangla`/`English` under `snake_case`, not `Language::code()`.
  `code()`/`from_code()` are for storage, IPC, and metrics only.
- Collections use `Vec` with a documented sort order or `BTreeMap` for stable
  ordering. **Never `HashMap` in a public data type**: import results and rule
  order must be deterministic for tests and golden corpora.
- Length/count limits are explicit fields on options types, with `Default`
  values. No input may grow a collection without a cap.

### 2.3 Error contract (all three crates)

Each crate exports one public error enum at `crate::error` and re-exports it at
the crate root. Each enum:

- derives `Debug` and `thiserror::Error`, and is marked `#[non_exhaustive]`;
- uses static `Display` strings (no interpolated paths or text);
- exposes the same shape for the daemon logger:

```rust
impl ExampleError {
    /// Stable identifier for the daemon logger's allowlisted `kind` field.
    pub fn kind(&self) -> &'static str;
    /// OS error code where one exists, otherwise `None`.
    pub fn code(&self) -> Option<i32>;
}
```

`kind()` strings are lowercase snake_case and unique per crate, e.g.
`lang_unsupported_schema`, `transliterate_invalid_rule`,
`compat_feature_disabled`. The daemon must never format the error itself into
a log record. **Callers must also never log `Debug` formatting or walk
`source()`**: `#[from] std::io::Error` and `#[from] serde_json::Error` remain
reachable there and can embed paths or text. Only `kind()` and `code()` are
logging-safe.

### 2.4 Fixture envelope (all three crates)

- UTF-8 JSON, LF line endings, no BOM, `schema: u32` as the first field.
- Unknown schema → the crate's `UnsupportedSchema { found, expected }` error;
  never best-effort parsing.
- Manifest paths are **relative**, use `/` separators, contain no `.` or `..`
  components, and are canonicalized under their fixture root before opening.
  This is the same policy style as `okkhor-compat` path validation (§5.3).
- Per-fixture byte cap: 8 MiB. Per-collection entry cap comes from the
  importing options type. The production importer default is 100,000 per asset
  (§3.3); **test fixtures assume `max_entries_per_asset = 1,000`**, set
  explicitly through `ImportOptions` so the cap is exercised deterministically.
- Every example JSON block in this document is valid JSON (no hexadecimal
  literals, comments, or trailing commas). Each crate's test suite asserts that
  its committed fixtures parse and that a schema bump is rejected.
- Fixture identifiers are logical names (`"avro"`, `"rule_bha"`) only. Do not
  put absolute paths or machine-specific names in fixtures.
- A test in each crate asserts its fixtures are valid against the declared
  schema and that a schema bump is rejected.

### 3.2 Data types (`assets.rs`)

```rust
use std::collections::BTreeMap;
use okkhor_core::Language;
use serde::{Deserialize, Serialize};
use crate::error::LangError;

pub const FIXTURE_SCHEMA: u32 = 1;

#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum AssetKind { Layout, Encoding, Dictionary }

#[derive(Debug, Clone, PartialEq, Eq, PartialOrd, Ord, Hash, Serialize, Deserialize)]
#[serde(transparent)]
pub struct LayoutId(String);

impl LayoutId {
    /// Known 0.3 layout codes. Custom ids are allowed but `is_known()` is false.
    pub const AVRO: &'static str = "avro";
    pub const NATIONAL: &'static str = "national";
    pub const PROBHAT: &'static str = "probhat";
    pub const BIJOY: &'static str = "bijoy";
    pub const BANGLISH: &'static str = "phonetic";
    pub const KHIPRO: &'static str = "khipro";

    /// Validates `[a-z0-9_-]`, length 1..=32. Mirrors `Language::from_code`.
    pub fn from_code(code: &str) -> Option<Self>;
    pub fn as_str(&self) -> &str;
    pub fn is_known(&self) -> bool;
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct LayoutMapping {
    /// Synthetic key token, ASCII, 1..=16 bytes (e.g. "a", "shift+a").
    pub key: String,
    /// NFC output string; validated at import with `okkhor_core::normalize_nfc`.
    pub output: String,
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct Layout {
    pub id: LayoutId,
    pub label: String,
    pub language: Language,
    /// Importer sorts by `key` and rejects duplicate keys.
    pub mappings: Vec<LayoutMapping>,
}

impl Layout {
    /// Binary search over sorted `mappings`. Normalizes `key` internally with
    /// `okkhor_core::normalize_lookup`; the importer applies the same
    /// normalization to stored keys. Callers pass the raw key token.
    pub fn lookup(&self, key: &str) -> Option<&str>;
}

#[derive(Debug, Clone, PartialEq, Eq, PartialOrd, Ord, Hash, Serialize, Deserialize)]
#[serde(transparent)]
pub struct EncodingId(String);

impl EncodingId {
    pub fn from_code(code: &str) -> Option<Self>; // same validation as LayoutId
    pub fn as_str(&self) -> &str;
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct EncodingEntry {
    /// Numeric code point or legacy byte value, 0..=0x10FFFF.
    pub code: u32,
    pub unicode: String, // NFC
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct EncodingTable {
    pub id: EncodingId,
    /// JSON array of `EncodingEntry` objects (not a JSON object). The importer
    /// sorts by `code` and rejects duplicate codes before storing.
    pub entries: Vec<EncodingEntry>,
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct DictionaryEntry {
    /// Normalized with `okkhor_core::normalize_lookup` at import.
    pub word: String,
    pub frequency: u32,
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct Dictionary {
    pub id: String,
    pub language: Language,
    /// Sorted by normalized `word`; no duplicates.
    pub entries: Vec<DictionaryEntry>,
}

impl Dictionary {
    /// Normalizes `word` internally with `okkhor_core::normalize_lookup`; the
    /// importer applies the same normalization to stored words, so callers
    /// pass the raw lookup string.
    pub fn get(&self, word: &str) -> Option<&DictionaryEntry>;
}

#[derive(Debug, Clone, Default, PartialEq, Eq, Serialize, Deserialize)]
pub struct ImportedAssets {
    pub layouts: BTreeMap<LayoutId, Layout>,
    pub encodings: BTreeMap<EncodingId, EncodingTable>,
    pub dictionaries: BTreeMap<String, Dictionary>,
}

impl ImportedAssets {
    pub fn is_empty(&self) -> bool;
    pub fn total_entries(&self) -> usize;
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum SkipReason {
    UnsupportedKind,
    UnsupportedSchema,
    InvalidId,
    DuplicateId,
    LimitExceeded,
    MalformedData,
    PathRejected,
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct UnsupportedAsset {
    pub kind: AssetKind,
    /// Logical name from the manifest, never a full path.
    pub name: String,
    pub reason: SkipReason,
}

#[derive(Debug, Clone, Default, PartialEq, Eq, Serialize, Deserialize)]
pub struct ImportReport {
    pub imported: u32,
    pub skipped: u32,
    pub unsupported: Vec<UnsupportedAsset>,
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub enum ImportedAsset {
    Layout(Layout),
    Encoding(EncodingTable),
    Dictionary(Dictionary),
}

// LangError is used by LayoutId/EncodingId validation in this module.
```

All output strings (layout outputs, encoding values, dictionary words) pass
through `okkhor_core::normalize_nfc` or `normalize_lookup` before being stored.
The importer never mutates or moves anything under an owner-provided legacy
folder; it reads committed synthetic fixtures only.

### 3.3 Importer API (`importer.rs`)

```rust
use std::path::Path;
use serde::Deserialize;
use crate::{AssetKind, ImportReport, ImportedAsset, ImportedAssets, LangError};

/// Envelope for `manifest.json` and every per-asset fixture file.
/// `schema` is read FIRST from a `serde_json::Value`; only after it equals
/// `FIXTURE_SCHEMA` is the payload deserialized into its typed form.
#[derive(Debug, Clone, PartialEq, Eq, Deserialize)]
pub struct FixtureEnvelope<T> {
    pub schema: u32,
    #[serde(flatten)]
    pub payload: T,
}

#[derive(Debug, Clone, PartialEq, Eq, Deserialize)]
pub struct Manifest {
    /// `schema` is consumed by `FixtureEnvelope`, not repeated here.
    pub assets: Vec<ManifestEntry>,
}

#[derive(Debug, Clone, PartialEq, Eq, Deserialize)]
pub struct ManifestEntry {
    pub kind: AssetKind,
    /// Relative, `/`-separated, no `.` or `..` components.
    pub path: String,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ImportOptions {
    /// Hard cap per asset; `LimitExceeded` when breached.
    pub max_entries_per_asset: usize,
    /// When true, the FIRST occurrence in manifest/array order wins and the
    /// duplicate is discarded without a report entry. See matrix below.
    pub allow_duplicates: bool,
    /// When true, any skipped asset aborts the whole import. See matrix below.
    pub strict: bool,
}
// Production default: max_entries_per_asset = 100_000, allow_duplicates = false,
// strict = false. Test fixtures use 1,000 (§2.4).

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ImportOutcome {
    pub assets: ImportedAssets,
    pub report: ImportReport,
}

/// Import every asset listed in `<root>/manifest.json`.
/// Root and all manifest paths are canonicalized; traversal is rejected.
pub fn import_fixture_dir(root: &Path, options: &ImportOptions) -> Result<ImportOutcome, LangError>;

/// Import one asset file. `path` is validated with the same policy.
pub fn import_asset(kind: AssetKind, path: &Path, options: &ImportOptions)
    -> Result<ImportedAsset, LangError>;
```

**Schema enforcement (I4):** `import_fixture_dir` first parses `manifest.json`
into `FixtureEnvelope<serde_json::Value>`; a missing or mismatched `schema`
yields `LangError::UnsupportedSchema { found, expected: FIXTURE_SCHEMA }`
(a missing field is `found = 0`). It then deserializes `payload` into
`Manifest`. Each asset file goes through the same envelope check before its
payload is deserialized into `Layout` / `EncodingTable` / `Dictionary`. These
public data types intentionally have no `schema` field; the envelope is the
only source of `found`, so a future schema bump cannot be silently ignored
through serde's default `deny_unknown_fields = false`.

**Duplicate and strict behavior (I3):** "duplicate" means (a) an asset id
repeated within a collection, or (b) a mapping key, encoding code, or
dictionary word repeated inside one asset. The first occurrence in manifest
or array order always wins.

| `allow_duplicates` | `strict` | Behavior |
| --- | --- | --- |
| `false` (default) | `false` (default) | Whole duplicate asset is skipped; append `UnsupportedAsset { kind, name, reason: SkipReason::DuplicateId }`, increment `skipped`; import continues with the first occurrence. |
| `false` | `true` | Duplicate is fatal: return `LangError::DuplicateId` immediately; no partial `ImportOutcome` is returned. |
| `true` | `false` | Duplicate occurrences are discarded silently (no `unsupported` entry, no error); first occurrence retained. |
| `true` | `true` | Same as `true`/`false`: an explicitly allowed duplicate is not a skip, so `strict` has nothing to escalate. |

Other skip reasons map to errors under `strict = true` as follows:
`UnsupportedSchema → LangError::UnsupportedSchema`,
`PathRejected → LangError::UnsafePath`,
`LimitExceeded → LangError::LimitExceeded`,
`DuplicateId → LangError::DuplicateId`,
and `UnsupportedKind | InvalidId | MalformedData →
LangError::InvalidData { reason }` with a static reason string. Under
`strict = false`, each of these is recorded in `ImportReport.unsupported` with
its matching `SkipReason`. `import_fixture_dir` never panics on malformed input
and returns deterministic `BTreeMap` contents plus an `unsupported` list sorted
by `(kind, name, reason)`.

### 3.4 Error type (`error.rs`)

```rust

#[derive(Debug, Error)]

pub enum LangError {
    #[error("fixture I/O failed")]
    Io(#[from] std::io::Error),
    #[error("fixture JSON is invalid")]

    pub fn kind(&self) -> &'static str; // e.g. "lang_unsupported_schema"
    pub fn code(&self) -> Option<i32>; // Io -> raw_os_error(), else None
```

### 3.6 Required tests (Task 1)

- **Every committed fixture parses as JSON** (assert with `serde_json::from_str`
  on each file, including the four examples in §3.5) and deserializes through
  `FixtureEnvelope` with `schema == FIXTURE_SCHEMA`.
- Valid manifest import with `ImportOptions { max_entries_per_asset: 1_000, .. }`;
  schema mismatch at both manifest and asset level (`found` read from the
  envelope, including a missing `schema` field).
- Relative/traversal/absolute path rejection; symlink escape rejection
  (Windows); duplicate id, mapping key, encoding code, and dictionary word
  across all four `allow_duplicates` × `strict` combinations from §3.3, with
  assertions on the exact `SkipReason` / `LangError` variant and on which
  occurrence wins.
- Entry-limit enforcement; NFC normalization; deterministic ordering and serde
  round-trip; `Display` contains no full path; no real legacy file read.
- End with an empty `ImportedAssets` fallback case to prove the daemon can
  degrade safely.

## 4. Crate contract: `okkhor-transliterate` (Task 2)

Responsibility: pure transliteration rule engine and Bangla/English
normalization helpers. **No dependency on `okkhor-lang`**, no I/O, no regex,

### 4.2 Normalization helpers (`normalize.rs`)

```rust
/// ASCII lowercase, then `okkhor_core::normalize_lookup` for trim/collapse.
pub fn normalize_roman(input: &str) -> String;

/// `okkhor_core::normalize_nfc`. Preserves whitespace, ZWJ/ZWNJ, and case.
pub fn normalize_bengali(input: &str) -> String;

/// Canonical rule-lookup key: NFC, trim/collapse whitespace, ASCII lowercase.
/// Non-ASCII letters are left unchanged. Used by the importer and the engine.
pub fn normalize_key(input: &str) -> String;

/// Delegates to `okkhor_core::contains_bengali`.
pub fn is_bengali_script(input: &str) -> bool;
```

All four are pure, deterministic, and bounded by input length. Bengali
grapheme/cursor movement is **out of scope** for this crate in 0.3; it remains
a Bornomala/golden-corpus workstream item. Do not add a Unicode segmentation
dependency without a new ADR.

### 4.3 Rule types (`rules.rs`)

```rust
use okkhor_core::Language;
use serde::{Deserialize, Serialize};
use crate::error::TransliterateError;

pub const RULE_SCHEMA: u32 = 1;

#[derive(Debug, Clone, PartialEq, Eq, PartialOrd, Ord, Hash, Serialize, Deserialize)]
#[serde(transparent)]
pub struct RuleId(String);

impl RuleId {
    pub fn from_code(code: &str) -> Option<Self>; // [a-z0-9_-], 1..=32
    pub fn as_str(&self) -> &str;
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct TransliterationRule {
    pub id: RuleId,
    /// Raw ASCII roman prefix as parsed, 1..=32 bytes. `normalize_key` is
    /// applied by `RuleTransliterator::new`, which also enforces ASCII-only
    /// explicitly (non-ASCII input is `InvalidRule { reason: "non_ascii_input" }`).
    pub input: String,
    /// Raw output as parsed, 1..=64 chars; NFC-validated by
    /// `RuleTransliterator::new`.
    pub output: String,
    /// Must be `Language::Bangla` in 0.3; validated by `RuleTransliterator::new`.
    pub language: Language,
    /// Lower wins on equal-length prefix matches. Default 100.
    pub priority: u16,
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct RuleSet {
    pub schema: u32,
    /// Parsed in file order. `RuleTransliterator::new` normalizes, validates,
    /// and sorts this into engine order (`input` length descending, `priority`
    /// ascending, `id` ascending).
    pub rules: Vec<TransliterationRule>,
}

impl RuleSet {
    /// Checks `schema == RULE_SCHEMA` (otherwise
    /// `UnsupportedSchema { found: schema, expected: RULE_SCHEMA }`) and
    /// deserializes shape and id syntax only. It does NOT normalize, sort,
    /// dedup, or validate language, length, or NFC.
    pub fn from_json_str(json: &str) -> Result<Self, TransliterateError>;
    pub fn len(&self) -> usize;
    pub fn is_empty(&self) -> bool;
}
```

**Normalization/sorting ownership (I7)** is split deterministically:

1. `RuleSet::from_json_str` owns: schema check, JSON parsing, field presence,
   and `RuleId` syntax validation. It preserves file order.
2. `RuleTransliterator::new` owns: `normalize_key` on each `input`; explicit
   ASCII-only check on normalized `input` (1..=32 bytes); NFC check and 1..=64
   char check on `output`; `language == Bangla`; duplicate normalized `id`
   (`DuplicateRuleId`) and duplicate normalized `input` with a different id
   (`InvalidRule { reason: "duplicate_rule_input" }`); sorting by
   (`input` length descending, `priority` ascending, `id` ascending). It stores
   the resulting immutable, engine-ordered view. `transliterate` sees only
   that view and performs no normalization or sorting.

### 4.4 Engine API (`engine.rs`)

```rust
use okkhor_core::Candidate;
use crate::{RuleId, RuleSet, TransliterateError};

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct TransliterationOptions {
    /// Hard cap on returned outputs; default 8.
    pub max_candidates: usize,
    /// Emit a candidate when only a prefix of a rule matched; default true.
    pub allow_partial: bool,
}

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct TransliterationOutput {
    pub text: String,
    pub language: okkhor_core::Language,
    /// 0.0..=1.0; derived from rule priority only, never from user data.
    pub confidence: f32,
    pub rule_id: RuleId,
}

impl TransliterationOutput {
    /// Bridge into the existing shared candidate/ranking path.
    /// Sets `source = CandidateSource::Transliteration` and
    /// `features.phonetic_score = confidence`.
    pub fn into_candidate(self) -> Candidate;
}

pub trait TransliteratorEngine {
    /// Pure, deterministic, no I/O. Outputs ordered by match quality.
    fn transliterate(&self, input: &str, options: &TransliterationOptions)
        -> Vec<TransliterationOutput>;
}

#[derive(Debug, Clone)]
pub struct RuleTransliterator { /* owns an immutable RuleSet */ }

impl RuleTransliterator {
    /// Applies all normalization, validation, and sorting listed in §4.3.
    /// Returns `TransliterateError` only from this construction step.
    pub fn new(rules: RuleSet) -> Result<Self, TransliterateError>;
    pub fn rule_count(&self) -> usize;
}

impl TransliteratorEngine for RuleTransliterator {
    fn transliterate(&self, input: &str, options: &TransliterationOptions)
        -> Vec<TransliterationOutput>;
}
```

Matching rules (scaffold semantics for 0.3):

1. Normalize the input with `normalize_key`. If `input.len() >= 256` (the
   ≥256-byte threshold), return an empty `Vec`. `transliterate` is infallible:
   no error value is constructed, no error type from another crate is
   referenced, and no panic occurs.
2. Literal prefix matching only — **no regex dependency** in this sprint.
3. Order: longest matched `input` first; ties by lower `priority`, then
   ascending `RuleId`. Deduplicate identical outputs, keeping the best rule.
4. Respect `max_candidates` as a hard cap; `allow_partial = false` emits only
   full-input matches.
5. Full phonetic/conjunct behavior is a later milestone. Mark the engine
   `scaffold` with `TODO(Task 2, milestone 0.3/0.4)` in docs/comments where
   appropriate.

### 5.3 DLL path validation (`path.rs`)

```rust
use std::path::{Path, PathBuf};
use crate::{AdapterKind, CompatError}; // AdapterKind/CompatError from sibling modules

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct DllPathPolicy {
    /// Absolute roots the daemon explicitly allowlists. Empty by default:
    /// no DLL can be loaded until the daemon configures a root.
    pub allowed_roots: Vec<PathBuf>,
    /// Default 32_768 (Windows extended-length path budget).
    pub max_path_bytes: usize,
    /// Default 128 * 1024 * 1024.
    pub max_file_bytes: u64,
}
// Default: allowed_roots = vec![], max_path_bytes = 32_768,
//          max_file_bytes = 128 * 1024 * 1024.

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ValidatedDllPath {
    path: PathBuf,        // canonical absolute path, private
    adapter: AdapterKind,
}

impl ValidatedDllPath {
    /// Validate before any OS loader call. Rules in the order below.
    pub fn validate(path: &Path, adapter: AdapterKind, policy: &DllPathPolicy)
        -> Result<Self, CompatError>;

    /// Canonical absolute path. Never the caller's original string.
    pub fn path(&self) -> &Path;
    pub fn adapter(&self) -> AdapterKind;
}
```

Validation rules (all must pass):

1. `adapter.is_enabled()` is true (feature gate first, cheapest check).
2. `path.is_absolute()`; on Windows allow only a disk or UNC prefix.
3. No component equal to `..` or `.` in the input path.
4. Extension is `dll` (ASCII case-insensitive).
5. File name equals `adapter.dll_file_name()` (case-insensitive), preventing
   one adapter from loading another adapter's library.
6. Canonicalize the path and every allowed root; the canonical path must be
   under at least one canonical root (`starts_with`). This defeats junction and
   symlink escape.
7. Canonical target is a file; byte length ≤ `max_path_bytes`; file size ≤
   `max_file_bytes`.
8. Return the canonical path. Errors carry only static reason strings, logical
   `AdapterKind` values, and optional numeric OS codes, exactly as declared in
   §5.6: `InvalidDllPath` has a static `reason` (no adapter),
   `PathOutsideAllowlist` and `UnsupportedPlatform` have no fields,
   `LoadFailed`/`MissingExport`/`BoundExceeded`/`NotLoaded`/
   `FeatureDisabled` carry `AdapterKind` (and `LoadFailed` a numeric code).
   **No full path is stored or formatted in any variant.**

The allowlist is supplied by the daemon from explicit owner configuration
(e.g. an owner-provided home). Never derive it from the current working
directory, `PATH`, or an untrusted environment variable in a shipped path.

### 5.4 Adapter registry (`adapter.rs`)

```rust
use std::path::Path;
use serde::{Deserialize, Serialize};
use crate::{CompatError, DllPathPolicy, ValidatedDllPath};

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum AdapterKind { WordTrie, SentenceTrie, Translator, Caret, EmojiManager }

impl AdapterKind {
    pub const ALL: [Self; 5] = [ /* all five */ ];

    /// Cargo feature name: "word-trie", "sentence-trie", "translator",
    /// "caret", "emoji-manager".
    pub fn feature_name(self) -> &'static str;

    /// DLL file name constant only: "word_trie.dll",
    /// "_sentencetrie_native.dll", "translator.dll", "caret.dll",
    /// "emoji_manager.dll". Names are not proprietary bytes.
    pub fn dll_file_name(self) -> &'static str;

    /// True only when the corresponding Cargo feature is compiled in.
    pub fn is_enabled(self) -> bool; // cfg!(feature = "...") per arm
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct AdapterStatus {
    pub kind: AdapterKind,
    pub enabled: bool,
    pub loaded: bool,
}

/// Opaque handle. No raw pointer accessors, no `Deref`, no `Send`/`Sync`.
/// Created, used, and dropped on the loading thread only.
#[derive(Debug)]
pub struct AdapterHandle { /* private */ }

impl AdapterHandle {
    pub fn kind(&self) -> AdapterKind;
    // Adapter-specific safe methods are added behind their feature gates in
    // later milestones. TODO(Task 3): scaffold marker, no stub that looks done.
}

#[derive(Debug)]
pub struct AdapterRegistry { /* [Option<AdapterHandle>; 5] fixed slots + policy */ }

impl AdapterRegistry {
    pub fn new(policy: DllPathPolicy) -> Self;
    pub fn statuses(&self) -> Vec<AdapterStatus>; // ordered by AdapterKind
    pub fn is_loaded(&self, adapter: AdapterKind) -> bool;

    /// Feature gate -> path validation -> platform check -> loader.
    /// All unsafe lives below this seam; nothing unsafe escapes.
    pub fn load(&mut self, path: &Path, adapter: AdapterKind) -> Result<(), CompatError>;

    /// Release the library. Idempotent; `NotLoaded` only if explicitly requested
    /// for an adapter that was never loaded (document which behavior is chosen).
    pub fn unload(&mut self, adapter: AdapterKind) -> Result<(), CompatError>;
}

impl Drop for AdapterRegistry {
    fn drop(&mut self); // unload everything on the loading thread
}
```

`AdapterHandle` is deliberately `!Send + !Sync` in 0.3 (use a private
`PhantomData<std::rc::Rc<()>>` field). The daemon must create the registry on the
thread that will own adapter calls, normally at startup.

Implementation note: the contract sketch formerly named `BTreeMap<AdapterKind,
AdapterHandle>` for the registry and `PhantomData<*const ()>` for the marker;
the implementation uses a fixed `[Option<AdapterHandle>; 5]` slot array indexed
by `AdapterKind` declaration order (which preserves the `statuses()` ordering
guarantee) and a `PhantomData<std::rc::Rc<()>>` marker (a raw-pointer marker
would itself be `Send + Sync` and would not pin the handle). The decisions —
order-preserving registry, `!Send + !Sync` handle, loading-thread ownership —
are unchanged.

### 5.5 FFI boundary contract (`ffi.rs`, private, `cfg(windows)`)

```rust
// Every function below is `pub(super)` and unsafe to call.
// Each call site carries `// SAFETY: <invariant>`; no public API exposes these.

pub(super) unsafe fn load_library(path: &ValidatedDllPath)
    -> Result<*mut std::ffi::c_void, CompatError>;

pub(super) unsafe fn free_library(handle: *mut std::ffi::c_void)
    -> Result<(), CompatError>;

pub(super) unsafe fn resolve_proc(handle: *mut std::ffi::c_void, name: &[u8])
    -> Result<Option<*mut std::ffi::c_void>, CompatError>;
```

Required invariants:

- `load_library` is called only with a `ValidatedDllPath`; use
  `LoadLibraryExW` with an absolute canonical path and
  `LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR | LOAD_LIBRARY_SEARCH_SYSTEM32`. Never load
  from the cwd or a relative path. No `LoadLibrary` on non-Windows.
- `free_library` is called only with a non-null handle owned by a live
  `AdapterHandle`, exactly once, on the loading thread.
- `resolve_proc` takes a NUL-terminated ASCII export name buffer and a live
  handle; symbol names are compile-time constants from this crate, never
  user-supplied.
- Every FFI call is bounded: explicit UTF-8↔UTF-16 conversion, maximum output
  byte caps, no Rust references across the boundary, no panics crossing FFI.
- FFI is startup/shutdown only. No adapter call from the keyboard hook or the
  per-keystroke candidate path.
- Real DLL bytes are never committed, copied, hashed into fixtures, or
  executed by tests.

## 6. Integration with the daemon (lead-owned, Tasks 1–3 do not edit the daemon)

### 6.1 Startup composition

1. **Lang:** `import_fixture_dir` runs once against a synthetic or
   owner-provided fixture directory; the resulting `ImportedAssets` is held in
   an `Arc` by the input worker. On failure, use an empty `ImportedAssets` and
   log `scope=lang`.
2. **Transliterate:** build `RuleSet::from_json_str` from a bundled synthetic
   `include_str!`, then `RuleTransliterator::new`; hold it in an `Arc`. On
   failure, disable the transliteration source and log `scope=transliterate`.
3. **Compat:** build `DllPathPolicy` from explicit allowlisted roots, create
   `AdapterRegistry` on the owning thread, and load only feature-enabled
   adapters. On any failure, disable that adapter, continue with pure Rust, and
   log `scope=compat`. No adapter is required for typing in 0.3.

### 6.2 Runtime data flow

```text
input worker (not the hook callback)
  prefix + roman_input + layout
        │
        ├─ okkhor-lang: Layout::lookup / Dictionary::get (bounded, in-memory)
        ├─ okkhor-transliterate: TransliteratorEngine::transliterate
        │        └─ TransliterationOutput::into_candidate()
        │              -> okkhor_core::Candidate (source = Transliteration)
        └─ okkhor_core::Ranker, implemented by okkhor_learn::Smriti -> Vec<Suggestion>
```

`Ranker` is a trait in `okkhor-core`; `okkhor-learn` does not export a `Ranker`
of its own — it exports `Smriti`, which implements the core trait. The daemon
calls `okkhor_core::Ranker::rank` on a `Smriti` instance.

`SuggestionRequest::layout` carries the `LayoutId` string as **metadata only**
in 0.3. The Smriti pair key remains `(language, normalized roman input,
output)` per `docs/learning.md`, which lists "should transliteration pairs
include the active layout in the key?" as an open question. Including layout
in the key is a lead decision tracked in §8, not behavior implemented by Tasks
1–3. `okkhor-compat` appears **only** at startup/shutdown in this milestone;
no adapter is on the keydown path.
