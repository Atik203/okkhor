# Replay harness (0.6 Task 1)

Offline, synthetic-only evaluation for the candidate engine and the Smriti
baseline. No network, no user data, no legacy execution. Normative details
live in code (`crates/okkhor-train`); this note explains the shape.

## Format v1 (JSONL)

One JSON object per line, UTF-8, `\n` terminated:

```json
{"schema":1,"case_id":"bn_0007","language":"bangla","layout":"avro",
 "prefix":"ভা","context":[],"expected":["ভালো"],
 "shown":["ভালো","ভাই"],"accepted":0,
 "candidates":["ভালো","ভাই","ভাত"]}
```

- `schema` is `1`; a missing field reports `found = 0`.
- `case_id` matches `[a-z0-9_-]` (1..=64 bytes), unique per file.
- `prefix` is 1..=255 bytes; `context` holds ≤ 8 words.
- `expected` holds 1..=5 NFC strings; `shown`/`candidates` are non-empty,
  bounded (≤ 32 / ≤ 64), NFC.
- `accepted` is `null` or a valid index into `shown`.

Validation is fail-closed: malformed JSON, bad schema, duplicate ids,
overlong fields, non-NFC text, and out-of-range `accepted` are all rejected.
Empty files are rejected.

## Dataset

`crates/okkhor-train/data/synthetic-replay.jsonl` (240 cases, seed
`20261123`) is generated by

```powershell
cargo run -p okkhor-train --bin okkhor-replay -- `
  --generate --out crates/okkhor-train/data/synthetic-replay.jsonl `
  --seed 20261123 --cases 240
```

The generator expands hand-authored synthetic word lists with a seeded
SplitMix64 stream; the same seed yields byte-identical output (SHA-256
recorded in `docs/performance.md`). The file is committed; regeneration is a
visible diff. Generation refuses `< 200` cases. Nothing is downloaded and no
real corpus is embedded: quality claims beyond the synthetic distribution
are out of scope (see the **synthetic-only** caveat in `docs/performance.md`).

## Training split

`okkhor-train-fit --replay <path> --out <model.json>` fits the Tier 1 logistic
reranker. The split is by case, not by row:

- 80/20 train/validation by the first 8 bytes of `SHA-256(case_id)`, read as a
  big-endian integer modulo 100: `< 80` is train, otherwise validation. The
  same case always lands in the same split, and reordering the file changes
  nothing.
- Fewer than 200 cases is rejected.
- Standardization (means/scales) comes from the training split only and is
  saved in the model JSON.
- Fit is full-batch gradient descent (zero init, 500 iterations, learning rate
  `0.05`, L2 `1e-4`) with a seeded per-iteration shuffle of case order and class
  weight `negatives / positives`.
- The model JSON is byte-identical for the same seed, replay, and `--trained-at`
  (default `1970-01-01T00:00:00Z`); no wall-clock read is part of the fit.
- Validation top-1/top-5/MRR score each case's closed candidate pool with the
  fitted model and rank on `(score desc, text asc)`.

## Ranking and metrics

`okkhor-replay --replay <path> (--engine | --smriti)` rebuilds a fixed
fixture engine (dictionaries from the replay vocabulary, fixed synthetic
roman→Bangla rules, empty Smriti, default budgets) and scores every case:

- **engine**: full `CandidateEngine::suggest` from `prefix`/`context`
  (roman input synthesized from ASCII Bangla prefixes).
- **smriti**: cold-start `Smriti::rank` over the case's closed candidate pool
  (`base_score = 1/(1+position)`). Top-5 is therefore 1.0 by construction; the
  informative comparison is top-1/MRR/latency.

Conventions (mirroring the golden-corpus parity rule): top-1 compares
`ranked[0]` to `expected[0]`; top-5 checks any `expected` entry in the first
five; MRR uses the first hit's rank over the full list; keystroke savings per
case is `max(0, (expected_len − prefix_len) / expected_len)` on a top-1 hit,
`0` otherwise, averaged; acceptance rate is the fraction of cases with
`accepted.is_some()`. Latency is per-case ranking time with nearest-rank
p50/p95/p99, the same method as `okkhor-bench`.

Reports go to git-ignored `bench-out/` as `--json` or `--markdown`.

## Relation to other harnesses

- The 0.4 golden corpus (`crates/okkhor-engine/tests/fixtures/...`) pins
  engine parity on 3 cases; replay measures ranking quality on 240.
- `okkhor-bench --ranking/--candidates` measures latency on synthetic
  corpora; replay adds acceptance-labeled cases and segments.
- Task 2 reuses this harness for the hybrid A/B comparison.
