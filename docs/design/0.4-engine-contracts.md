# 0.4 engine contracts (normative)

- Status: Binding for the 0.4 candidate-engine sprint (see ADR 0011). From 0.9
  the layout field selects a real engine; ADR 0021 supersedes the older
  "metadata only" statement in this document.
- Owner: Task 1 (architect). Implementation is owned by Task 2; benchmarking by
  Task 3; integration by the lead.
- Scope: public contracts only. **No implementation code, no legacy binaries,
  no proprietary assets, no real user text, and no secrets are part of this
  contract.**
- Companion decisions: ADR 0001 (crate boundaries), ADR 0005 (legacy FFI),
  ADR 0008 (benchmark harness), ADR 0010 (0.3 contracts), ADR 0011 (this
  contract).

This document is the single source of truth for `okkhor-engine`. Where it
conflicts with a task description, this document wins; escalate rather than
silently widening scope.

## 1. Non-negotiable invariants

1. **Dependency closure is fixed.** `okkhor-engine` depends only on
   `okkhor-core`, `okkhor-lang`, `okkhor-transliterate`, and `okkhor-learn`.
   It never depends on `okkhor-compat`, `okkhor-win`, `okkhor-storage`, the
   daemon, I/O, regex, or network crates. It carries
   `#![forbid(unsafe_code)]`.
2. **No changes to `okkhor-core`** in this milestone. `SuggestionRequest`,
   `Suggestion`, `Candidate`, `CandidateSource`, `RankingFeatures`, `Ranker`,
   `Language`, and `normalize_lookup` are consumed as-is. A type that must be
   shared with another crate is a design smell: define it locally or propose a
   core change via a new ADR and the lead.
3. **Typing path stays clean.** `suggest` performs no I/O, FFI, network calls,
   logging of text, or unbounded allocation. Construction/import happens once
   at daemon startup; `suggest` is a bounded in-memory computation on the input
   worker.
4. **Privacy by construction.** Public error `Display` text never contains
   user text, fixture contents, full paths, window titles, or proprietary
   asset bytes. Errors expose a stable `kind()` and an optional numeric
   `code()` for the daemon's allowlisted logger. Callers never log `Debug`
   formatting and never walk `source()`.
5. **Fixtures are synthetic only.** All test data is authored JSON committed
   under `crates/okkhor-engine/tests/fixtures/synthetic/`. No legacy `*.bin`,
   `.nmsLayout`, `.nmsEnco`, binary blobs, `settings.pkl`, or executed legacy
   application.
6. **Real-format importers are out of scope.** No `WTR1`-magic binary-trie
   parser and no `.nmsLayout`/`.nmsEnco` deserializer ship in 0.4 (see §8).
   Synthetic fixtures remain the corpus.
7. **Honesty.** Unfinished behavior is marked `scaffold` or `TODO` with an
   owner Task and a roadmap milestone; no placeholder may look finished.

## 3. Configuration: per-language budgets

```rust
use okkhor_core::Language;
use serde::{Deserialize, Serialize};

/// Cap for one stage of the pipeline in one language.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub struct LanguageBudget {
    /// Max dictionary prefix hits admitted per query. Default 20.
    pub max_prefix_hits: usize,
    /// Max transliteration outputs admitted per query. Default 8.
    pub max_transliteration_hits: usize,
    /// Max candidates entering the ranker after merge+dedup. Default 24.
    pub max_merged: usize,
    /// Hard ceiling for `SuggestionRequest::limit`. Default 10.
    pub max_limit: usize,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub struct EngineConfig {
    pub bangla: LanguageBudget,
    pub english: LanguageBudget,
}

impl EngineConfig {
    /// Documented defaults (§3 table). Rejects zero budgets (see §6).
    pub fn new(bangla: LanguageBudget, english: LanguageBudget)
        -> Result<Self, EngineError>;
}

impl Default for EngineConfig {
    fn default() -> Self; // the table below; infallible
}

impl LanguageBudget {
    pub fn for_language(config: &EngineConfig, language: Language) -> Self;
}
```

Default table (normative for `EngineConfig::default()`):

| Field | Bangla | English | Rationale |
| --- | --- | --- | --- |
| `max_prefix_hits` | 20 | 20 | dictionary fan-out is bounded and cheap |
| `max_transliteration_hits` | 8 | 2 | Bangla romanized input fans out; English rarely needs transliteration |
| `max_merged` | 24 | 24 | ranker input stays under the 2 ms rerank budget |
| `max_limit` | 10 | 10 | UI shows at most top-10 from this path |

Budgets are validated once at construction: every field must be ≥ 1 and
`max_merged >= max(requested limit after clamp)` is enforced per query by
truncation, not by error. `suggest` clamps `request.limit` to
`1..=budget.max_limit` (a `limit` of 0 yields an empty `Vec`, not an error).

## 4. Engine API

```rust
use okkhor_core::{Ranker, Suggestion, SuggestionRequest};
use okkhor_lang::Dictionary;
use okkhor_learn::Smriti;
use okkhor_transliterate::{RuleTransliterator, TransliterationOptions};
use crate::{EngineConfig, EngineError};

#[derive(Debug)]
pub struct CandidateEngine<'a> {
    /* private: borrowed dictionaries, transliterator, Smriti, config */
}

impl<'a> CandidateEngine<'a> {
    /// Borrow already-constructed components. Validates budgets once.
    /// Clones nothing large; owns no I/O handle.
    pub fn new(
        dictionaries: &'a [Dictionary],
        transliterator: &'a RuleTransliterator,
        smriti: &'a Smriti,
        config: EngineConfig,
    ) -> Result<Self, EngineError>;

    /// Infallible query: degradation means fewer candidates, never an error.
    pub fn suggest(&self, request: &SuggestionRequest) -> Vec<Suggestion>;

    pub fn config(&self) -> &EngineConfig;
}
```

Lifetime note: the engine borrows its components (`'a`) so the daemon owns
exactly one copy of each asset. No `Arc` requirement is imposed by this
contract; the daemon chooses its sharing mechanism.

`TransliterationOptions` passed internally is derived from the budget:
`max_candidates = budget.max_transliteration_hits`, `allow_partial = true`
(§5, stage 2).

## 5. Composition order (normative)

`suggest` executes exactly these stages, in order. Reordering requires a new
ADR.

```text
request
  │  (0) normalize once: prefix = normalize_lookup(request.prefix),
  │      roman = request.roman_input.map(normalize_lookup)
  ├─ (1) dictionary prefix lookup over `dictionaries`
  ├─ (2) transliteration application for Romanized input
  ├─ (3) merge + dedup
  ├─ (4) Smriti rank via okkhor_core::Ranker::rank
  └─ (5) top-N truncate to clamped limit
```

**Stage 0 — normalize once (engine-owned).** The engine applies
`okkhor_core::normalize_lookup` to `request.prefix` and, when present,
`request.roman_input` exactly once and passes the normalized strings to every
later stage. Downstream helpers (`Dictionary::get`,
`RuleTransliterator::transliterate`, `Smriti::rank`) also normalize
internally; that is idempotent and stays correct, but no stage may derive a
*distinct* key (no lowercasing except through the shared normalizer, no
trimming variant). If the normalized prefix is empty or the raw input is
≥ 256 bytes (matching the transliteration crate's overlong threshold),
`suggest` returns an empty `Vec` immediately.

**Stage 1 — dictionary prefix lookup.** Scan the borrowed `dictionaries`
filtered by `request.language`; admit entries whose normalized `word` starts
with the normalized prefix, in dictionary order, up to
`budget.max_prefix_hits`. Each hit becomes a `Candidate` with
`source = CandidateSource::Dictionary` and
`features.base_score` derived from the entry's rank position (earlier entry =
higher base score; exact formula is implementation detail but must be
monotonic and documented in code). English queries use this stage as their
primary source.

**Stage 2 — transliteration application.** Applies when the request carries a
non-empty `roman_input`, or when `request.language == Language::Bangla` and
the normalized prefix is pure ASCII (the prefix itself is then the roman
input). Calls `transliterator.transliterate(roman,
&TransliterationOptions { max_candidates:
budget.max_transliteration_hits, allow_partial: true })` and converts each
output via `TransliterationOutput::into_candidate()` (hence
`source = CandidateSource::Transliteration`,
`features.phonetic_score = confidence`). Results already arrive ordered by
match quality; the engine never re-sorts within this stage.

**Stage 3 — merge + dedup.** Concatenate stage-1 and stage-2 candidates
(dictionary first), then dedup by `(language, text)`, keeping the first
occurrence — except that a `Transliteration` candidate replaces an earlier
`Dictionary` candidate for the same key when its `phonetic_score > 0.0`,
carrying the transliteration source forward. Truncate to
`budget.max_merged`, dictionary-priority order preserved. Dedup is exact
string equality on already-normalized text; no fuzzy collapsing.

**Stage 4 — Smriti rank.** Call
`okkhor_core::Ranker::rank(smriti, request, merged)`. The engine passes the
*original* `request` (with caller `context`, `now_ms`, and `layout`
metadata) so recency and bigram scoring stay deterministic per caller
time. `layout` remains metadata only until the Smriti pair-key question
closes (ADR 0011 context); the engine must not synthesize layout-qualified
keys of its own.

**Stage 5 — top-N truncate.** Truncate the ranked `Vec<Suggestion>` to
`min(request.limit clamped to 1..=budget.max_limit, ranked.len())`,
preserving rank order. A `limit` of 0 yields an empty `Vec`.

## 6. Error type

Construction is the only fallible operation; `suggest` never constructs or
returns an error.

```rust
use thiserror::Error;

#[derive(Debug, Error)]
#[non_exhaustive]
pub enum EngineError {
    #[error("engine budget is invalid")]
    InvalidBudget,
    #[error("engine component is missing")]
    MissingComponent,
    #[error("unsupported golden schema {found}; expected {expected}")]
    UnsupportedSchema { found: u32, expected: u32 },
    #[error("golden corpus data is malformed: {reason}")]
    InvalidGolden { reason: &'static str },
}

impl EngineError {
    /// Stable identifier for the daemon logger allowlist, e.g.
    /// "engine_invalid_budget".
    pub fn kind(&self) -> &'static str;
    /// Always `None` in this crate (no OS call underlies either variant).
    pub fn code(&self) -> Option<i32>;
}
```

- `InvalidBudget`: any budget field is 0, or `max_merged == 0`. Returned only
  by `EngineConfig::new` / `CandidateEngine::new`.
- `MissingComponent`: reserved for a future owned-handle constructor; the
  borrowed `new` in §4 never needs it, but the variant keeps the enum
  extensible without breaking matches. Must not be constructed spuriously to
  satisfy a test.
- `UnsupportedSchema { found, expected }`: the golden-corpus loader
  (`GoldenCorpus::from_json_str`, §8) reads `schema` before any payload
  deserialization; a missing field is `found = 0`. Never best-effort parsed.
- `InvalidGolden { reason }`: golden-corpus shape failures (bad id syntax,
  duplicate id, length-cap breach, bad language code, non-NFC expected
  strings) with a static reason string. Mirrors
  `LangError::InvalidData` from the 0.3 contract.
- `Display` strings are static. No user text, fixture content, path, or asset
  bytes appear in any variant or message. `kind()` values are
  `"engine_invalid_budget"`, `"engine_missing_component"`,
  `"engine_unsupported_schema"`, `"engine_invalid_golden"`;
  `code()` is always `None` in this crate.

## 7. Determinism and bounded-allocation rules

1. **Deterministic output.** Identical dictionaries + identical rule set +
   identical `Smriti` state + identical `request` ⇒ byte-identical
   `Vec<Suggestion>`. No wall-clock reads, no RNG, no thread-timing input on
   the query path; `now_ms` arrives from the caller.
2. **Tie-break.** `Ranker::rank` (implemented by `Smriti`) orders by
   `(score desc, text asc)` via a stable sort (`total_cmp` on scores,
   then `text` comparison). The engine performs no re-sort after ranking:
   candidates that compare equal on both keys keep their §5 stage-3 merge
   order (dictionary hits before transliteration hits, each in stage order),
   which is deterministic for identical inputs. Two suggestions may therefore
   still compare equal on `(score, text)`; determinism here means identical
   inputs yield byte-identical output, not that no two elements compare
   equal. `Smriti`'s ordering is owned by `okkhor-learn` and is not changed
   by this ADR; a tertiary source-rank key would need its own ADR.
3. **No hash-order leakage.** No public type exposes a `HashMap`; engine
   scratch state uses `Vec`/`BTreeMap` only. `Smriti` internals are opaque to
   this contract, but the engine's own merge/dedup/truncate must not iterate
   any hash map.
4. **Bounded allocation.** Per query: at most
   `max_prefix_hits + max_transliteration_hits` stage candidates,
   `max_merged` merged candidates, and `max_limit` returned suggestions, each
   string bounded by the caller's input length plus committed asset word
   lengths. No `Vec::with_capacity` larger than the applicable budget, no
   recursion, no per-query thread spawn.
5. **No I/O, no clock, no logging on the query path.** `suggest` takes `&self`
   and returns owned data; it opens no file, emits no log record, and reads no
   clock. The daemon logs only `kind()`/`code()` at its own layer.
6. **Float hygiene (engine stages only).** Scores produced by the engine's
   own stages (1–3: base scores, phonetic confidences) are finite `f32`;
   any non-finite value arising there is clamped to `0.0` before merge so
   ordering stays total. This rule does not cover `Smriti`'s internal
   scoring, which clamps to `f32::NEG_INFINITY` in `score_with` and is left
   unchanged by this contract. Task 2's determinism test (§10) must pin the
   observable behavior of the combined pipeline, including the bottom-rank
   placement of such pathological scores.

## 8. Golden corpus schema (synthetic only)

Location: `crates/okkhor-engine/tests/fixtures/synthetic/`. UTF-8 JSON, LF,
no BOM, a required `schema: u32` field, per-file cap 8 MiB. The loader reads
`schema` before deserializing any payload; field position within the JSON
object carries no meaning and is not enforced.

`corpus.json`:

```json
{
  "schema": 1,
  "cases": [
    {
      "id": "bn_bhalo_prefix",
      "prefix": "ভা",
      "roman_input": "bha",
      "language": "bangla",
      "layout": "avro",
      "context": ["আমি"],
      "expected_top5": ["ভালো", "ভাষা", "ভাত", "ভাবনা", "ভাই"]
    },
    {
      "id": "en_hel_prefix",
      "prefix": "hel",
      "language": "english",
      "layout": "avro",
      "context": [],
      "expected_top5": ["hello", "help", "held", "helm", "helix"]
    }
  ]
}
```

Field rules:

| Field | Type | Required | Rule |
| --- | --- | --- | --- |
| `schema` | `u32` | yes | must equal `GOLDEN_SCHEMA` (`1`); mismatch ⇒ `UnsupportedSchema`-class error, never best-effort parsing |
| `cases` | array | yes | 1..=10,000 entries; entry cap enforced by the test harness |
| `id` | string | yes | `[a-z0-9_-]`, 1..=64; unique within the file |
| `prefix` | string | yes | raw input prefix, 0..=255 bytes; normalized by the engine at query time |
| `roman_input` | string/null | no | raw Romanized input; absent means "derive per §5 stage 2" |
| `language` | string | yes | `"bangla"` or `"english"` (serde `Language`, snake_case — never `"bn"`/`"en"`) |
| `layout` | string/null | no | layout id as metadata (e.g. `"avro"`); recorded for future layout-aware ranking, not used as a rank key in 0.4 |
| `context` | array of string | yes | previous words, oldest first, 0..=8 entries; normalized by the engine |
| `expected_top5` | array of string | yes | 1..=5 NFC strings, most likely first; generic sample tokens only, never user text or legacy dumps |

Public types (`golden.rs`):

```rust
pub const GOLDEN_SCHEMA: u32 = 1;

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct GoldenCase {
    pub id: String,
    pub prefix: String,
    pub roman_input: Option<String>,
    pub language: Language,
    pub layout: Option<String>,
    pub context: Vec<String>,
    pub expected_top5: Vec<String>,
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct GoldenCorpus {
    pub schema: u32,
    pub cases: Vec<GoldenCase>,
}

impl GoldenCorpus {
    /// Parses and validates: schema check, id syntax + uniqueness, length
    /// caps, language/layout codes, NFC validation of expected strings.
    pub fn from_json_str(json: &str) -> Result<Self, EngineError>;
}
```

`GoldenCorpus::from_json_str` fails with `EngineError::UnsupportedSchema`
(§6) on schema mismatch (a missing `schema` field is `found = 0`); malformed
cases (bad id syntax, duplicate id, length-cap breach, bad language code,
non-NFC expected strings) fail with `EngineError::InvalidGolden` carrying a
static reason. The query path (`suggest`) never constructs any error.

## 9. Parity metric

```rust
#[derive(Debug, Clone, Copy, Default, PartialEq, Serialize, Deserialize)]
pub struct ParityReport {
    pub cases: u64,
    pub top1_hits: u64,
    pub top5_hits: u64,
    pub top1_rate: f64,
    pub top5_rate: f64,
}

/// Runs every corpus case through `engine.suggest` with
/// `limit = min(5, budget max_limit)` and scores ranks 1 and 1–5.
pub fn check_parity(engine: &CandidateEngine, corpus: &GoldenCorpus) -> ParityReport;
```

- **Top-1 hit:** `suggestions.first() == expected_top5.first()`.
- **Top-5 hit:** any of `expected_top5` appears in the first five suggestions
  (comparison on exact normalized text).
- Rates are `hits / cases` as `f64`; an empty corpus yields `0.0` rates with
  `cases == 0` (no division by zero, no panic).
- `check_parity` is a test/bench helper, never on the typing path. It builds
  each `SuggestionRequest` from the case (`prefix`, `language`, `layout`,
  `context`, `roman_input`, `now_ms = 0` for determinism) with
  `limit = min(5, budget max_limit)` — this `min(...)` form is the single
  normative statement of the parity limit.
- Latency is **not** part of this metric. Task 3 reports rank latency
  p50/p95/p99/max + correctness from a release build per
  `docs/performance.md`; no reference-machine claim is made on a shared
  desktop.

## 10. Required tests (Task 2)

- Stage order: dictionary-only, transliteration-only, and mixed queries each
  produce the §5 order; a reordering regression test pins merge priority.
- Normalization ownership: untrimmed / non-NFC prefix and `roman_input`
  variants return identical output to the clean form (engine normalizes
  once); overlong (≥ 256-byte) input yields an empty `Vec` without panic.
- Budgets: per-language caps enforced (`max_prefix_hits`,
  `max_transliteration_hits`, `max_merged`, `max_limit` clamp, `limit = 0`
  ⇒ empty); zero-budget construction returns `EngineError::InvalidBudget`.
- Determinism: repeated `suggest` calls are byte-identical; the two-level
  `(score desc, text asc)` tie-break with stable merge-order retention is
  pinned with crafted ties, including a case where score and text are equal
  across sources.
- Dedup: shared `(language, text)` across sources keeps exactly one entry
  with the §5 stage-3 source rule.
- Golden corpus: every committed fixture parses and validates through
  `GoldenCorpus::from_json_str`; schema bump is rejected; `check_parity`
  rates are exact on a hand-computed miniature corpus.
- Error contract: `Display` contains no input text; `kind()` values are the
  documented snake_case strings; `code()` is `None`.
- Purity: `#![forbid(unsafe_code)]` compiles; no test performs I/O outside
  the committed fixture dir, opens a real legacy file, or commits proprietary
  bytes.

## 11. Integration with the daemon (lead-owned; Task 2 does not edit the daemon)

1. **Startup:** the daemon constructs `ImportedAssets`, `RuleTransliterator`,
   and `Smriti` once (per the 0.3 §6.1 flow), then builds `EngineConfig` and
   `CandidateEngine::new` borrowing them. Construction failure disables the
   engine source and logs `scope=engine` with `kind()`/`code()`; typing
   continues on the remaining sources.
2. **Runtime:** the input worker (not the hook callback) calls `suggest` with
   a bounded `SuggestionRequest` and truncates to UI needs. The engine never
   touches the hook, the popup, or storage.
3. **Logging:** the lead adds `Scope::Engine` (`"engine"`) to the daemon
   logger. Until that gate lands, the logging call site cannot be written;
   Task 2 must not edit the logger.
4. **Self-check:** the lead extends `okkhor-daemon::self_check` with one
   synthetic engine case (prefix → expected top-1). Task 2 must not edit the
   daemon.

## 12. Deferred real-format importer (follow-up work, not 0.4)

The owner's granted findings describe the real legacy formats precisely
enough to scope — but not to implement — the follow-up:

- `*.bin` dictionaries: custom `WTR1` magic + version binary trie matching
  `word_trie.dll`.
- `.nmsLayout` / `.nmsEnco`: serialized dicts carrying metadata (`name`,
  `type`, `lang`, `dic`, `reverseMap`, `version`, `modification-time`,
  `developerName`), a `keyMap`, `compiledKeys`, and regex rules.

When the follow-up is scheduled it requires, in this order: (a) confirmed
redistribution rights, (b) test-validated parsers (never guessed formats, per
AGENTS.md rule 5), (c) an ADR or plan update covering the new importer crate
and its fixture policy, and (d) a disposable-VM differential run before any
parity claim cites real data. Nothing in 0.4 pre-reads, copies, or executes
those assets.

## 13. Deferred minors (accepted, non-blocking)
