# Okkhor 0.2.0 - input daemon

Status: **code-complete; manual Windows QA pending** in issue #8.

## Highlights

- Real Win32 low-level keyboard hook with dedicated hook thread and bounded queue.
- `Ctrl+Alt+Shift+P` pause hotkey and capture pause state.
- Unicode `SendInput` injector, guarded clipboard fallback, and native-control
  `WM_CHAR` fast path.
- Caret-aware, non-activating popup scaffold with per-monitor DPI placement.
- Per-user single-instance mutex and resident `okkhor daemon` mode.
- Tray icon with Pause/Resume and Exit; per-user autostart; redacted JSON-lines
  logging under `%LOCALAPPDATA%\Okkhor\logs`.
- Non-hook benchmark harness (`apps/okkhor-bench`) and a 103-row Windows QA
  matrix.

## Measured performance

Release build, shared Windows 11 desktop. The 100-iteration baseline and the
10,000-iteration stress run produced the same p99 band:

| Path | English p99 | Bangla p99 | Correctness |
| --- | ---: | ---: | --- |
| Native `WM_CHAR` fast path | 1.23 ms | 1.11 ms | 10,000/10,000 each |
| Universal `SendInput` | 7.44 ms | 6.64 ms | 100/100 each |
| Smriti ranking (2,000 iterations) | 209 us | 209 us | n/a |

Readback observation was 14–19 ms p99 and is a diagnostic, not an injector-call
claim.

## Known limitations

- Manual QA matrix execution is pending (#8); no Office, touch, RDP, or
  mixed-DPI hardware validation has been recorded.
- Universal `SendInput` remains above the 2 ms target on this shared desktop.
  Native controls use the fast path; browser/Electron/Office use `SendInput`.
- The popup uses a plain native scaffold; the full suggestion-list UI is 0.5.
- Tray Settings is a placeholder; `TaskbarCreated` re-add and log rotation are
  follow-ups.
- No installer, signing, updater, speech, or AI workers in this milestone.
- `autostart enable/disable` was not exercised against the real registry.

cargo run --release -p okkhor-bench -- --injection --iterations 100 --json
