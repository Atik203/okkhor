Channel: beta (portable, unsigned unless the owner signs the build)
Artifact: `Okkhor-0.8.1-win64-portable.zip`
SHA256: `27C3D77B13297AF6BD7DAAF5F2DD76E3DB9B0B3061640782F24EEEB77924C170`

This is a stability patch on top of 0.8.0. It does not add a new model, does
not train on user text, and does not change the hot-path architecture.

## What shipped

### Fixed

- **Suggestions appear from the first letter.** The English session's
  three-character gate is gone, and the engine no longer skips its dictionary
  prefix stages below two characters. One-letter prefixes now return real
  Bangla rows and English completions. The existing 240-hit / 2000-entry scan
  caps still bound a one-letter query.
- **Backspace works in both directions.** Because the gates are gone and the
  0.8 prefix cache is still in place, typing forward and backspacing to an
  earlier prefix return the same rows instead of an empty list. Tests now
  assert visible rows for `b`, `bh`, `bha` and `bhal`, and for English tokens
  after each Backspace.
- **The popup stays calm.** When the candidate rows, the highlighted row and
  the caret anchor have not changed, `show_candidates` now returns without
  cloning the rows, measuring text with GDI, moving the window or repainting.
  Row widths are measured once per font/DPI and cached. A genuine content
  change still repaints through the memory DC, coalesced to 30 ms. This is the
  safe form of "keep the card, only change the numbers": numbers follow row
  order, so a word change must repaint; an unchanged word list does nothing.
- **No blank can replace a word.** A commit whose encoded text is empty or
  consists only of whitespace and zero-width characters is rejected before
  `SendInput`. This closes the only code path that could erase a roman word and
  leave whitespace. A four-word sequential commit test covers the session
  path.

### Changed

- The layout selector now offers only **Avro (Phonetic)**. In 0.8.0 the picker
  also listed Khipro, Phonetic, Bangla (National), Bijoy and Probhat, but none
  of them selected a different engine: all six codes ran the same embedded
  Avro table, and Probhat/Bijoy-as-input-layout had no mapping data at all.
  Keeping them advertised was misleading. The old codes are still accepted in
  `settings.json` so existing profiles load unchanged. Bijoy remains a working
  separate *output encoding*. The stored Khipro/Phonetic/National JSON files
  are reference data, not runtime assets;
  `docs/superpowers/plans/0.8.1-layout-engine.md` records how to wire a real
  per-layout engine before advertising another layout.

## Known limits

- The build is unsigned unless the owner supplies a trusted Authenticode
  certificate. Windows SmartScreen/Defender will still warn, and the tester
  must choose "More info → Run anyway". See `docs/release.md` for the
  SignPath OSS option, the Microsoft false-positive submission, and a local
  Mark-of-the-Web removal for known testers.
- Real-key Windows QA (rows P-01..P-11 in `docs/qa/0.8-checklist.md`) is still
  the owner's pass. The hook ignores injected keys, so automated tests cannot
  replace it.
- Local accepted/correction learning and next-word suggestions remain 0.9
  work. No learned model is enabled by default.
- Non-Avro keyboard layouts remain unwired. Only the Avro table changes
  transliteration output in 0.8.1.
