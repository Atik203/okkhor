# SDD plan: 0.3 multi-agent sprint

## Goal

Parallelize the next development slice without sharing mutable files:

1. finish the remaining 0.2 QA evidence;
2. create the 0.3 module skeletons (`okkhor-lang`, `okkhor-transliterate`,
   `okkhor-compat`);
3. review every branch before merge;
4. let the lead merge branches and delete worktrees.

## Global constraints

- Windows 11 x64 first; no cross-platform promise.
- No secrets, no user text, no proprietary assets, no legacy executable.
- Synthetic QA fixtures only.
- REA may be used read-only on the legacy application's native DLLs and PE
  metadata under `LEGACY_APP_HOME` (owner-provided path, never committed). Never
  execute the legacy application, and never copy proprietary bytes into the
  repository.
- Each agent owns only the paths in its task. Root `Cargo.toml` may receive one
  workspace-member line for the agent's own new crate; the lead resolves merge
  conflicts.
- No agent pushes, merges, creates PRs, edits GitHub issues, or dispatches
  subagents. The lead does all GitHub integration.
- Every code agent runs: `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`.
- Every QA agent records pass/fail/evidence in its report; no real typing.
- Notepad restores prior text, so QA must select-all/delete before each inject
  test to avoid counting restored text as injected text.
- Report statuses: `DONE`, `DONE_WITH_CONCERNS`, `NEEDS_CONTEXT`, `BLOCKED`.

## Tasks

### Task A - Architect / core designer (blocking prerequisite)

Role: core-level architect. Produce `docs/design/0.3-core-contracts.md` and
`docs/adr/0010-core-contracts.md`. Define the exact public types, error types,
module dependency direction, and integration points shared by Tasks 1-3. No
implementation code. Tasks 1-3 must not start until this contract exists.

### Task 0 - Manager

Role: integration manager. Produce `integration-plan.md` with merge order,
shared-file risks, and a decision for each cross-task interface. No code.

### Task 1 - `okkhor-lang`

Create `crates/okkhor-lang` with layout/encoding/dictionary data types, a
synthetic-fixture importer, and unit tests. No real legacy files.

### Task 2 - `okkhor-transliterate`

Create `crates/okkhor-transliterate` with a transliteration rule engine skeleton,
Bangla/English normalization helpers, and unit tests. No dependency on
`okkhor-lang`.

### Task 3 - `okkhor-compat`

Create `crates/okkhor-compat` with a safe FFI boundary, DLL path validation,
feature flags per adapter, and stubbed tests. Do not load real DLLs in tests.

### Task 4 - QA target apps

Use `okkhor inject` against Notepad, VS Code, and a browser with synthetic text.
Update `docs/qa/0.2-matrix.md` with evidence. File findings in the report, not
GitHub.

### Task 5 - QA performance and memory

Run ranking/injection benchmarks and a bounded memory observation. Update
`docs/performance.md` only with reproducible numbers.

### Task 6 - Review code branches

Review Tasks 1-3 diffs for spec compliance and Rust quality. One reviewer for
lang/transliterate, one for compat/security boundaries.

### Task 7 - Review QA/docs

Review QA matrix and performance doc changes for evidence quality, privacy, and
unsupported claims.

### Task 8 - Docs/risk agent

Write `docs/adr/0011-multi-agent-sprint.md` capturing worktree isolation,
ownership rules, and merge risks. No code.

### Task 9 - Lead integration

The lead merges reviewed branches, resolves root `Cargo.toml` conflicts, runs
full checks, updates the milestone, and deletes worktrees.
