# 0.6 — Language data, Tier 1 reranker, and AI text worker

Plan of record for milestone 0.6. Binding rules: `AGENTS.md`, ADR 0002
(AI off the hot path), ADR 0007 (hybrid learning-to-rank),
`docs/model-roadmap.md`, `docs/security-privacy.md`.

Voice/speech is **not** in 0.6. It is the last feature phase (0.9), after the
keyboard, language data, model, and release mechanics are done; see
`0.9-voice.md`.

## Global constraints

- Typing is sacred. No model or AI call is reachable from the hook or input
  worker. A miss or outage returns the deterministic Smriti/engine result.
- No raw user text leaves the device. Training uses licensed public corpora or
  synthetic data generated from our own layouts and dictionaries.
- **Heavy datasets are downloaded and processed only on the cloud GPU**
  (`uiu-h200`), never on the local workstation and never committed. The local
  repo receives only manifests, checksums, small frozen fixtures, and model
  coefficients.
- Every learned model has a hard inference deadline, a baseline fallback, and a
  versioned feature schema. No ONNX, transformer, or GPU runtime in 0.6.
- AI is opt-in, cancellable, cached in memory, and never logs text.
- The worker is a separate process. A worker crash must not stop typing.
- No API keys committed. Providers are behind traits; tests use mocks.
- No cloud calls in CI. Network adapters are feature-gated and tested with a
  local fake server.

## Merge order

`1 → 2 → 3 → 4`. Task 2 depends on Task 1's replay set and feature
extraction. Task 3 is independent and may run in parallel once 0.5 is merged;
the lead resolves `Cargo.toml` conflicts.

## Task 1 — Dataset acquisition, manifests, feature schema, replay harness

Dataset acquisition runs on `uiu-h200` only, following
`docs/design/datasets.md` and the catalog in
`akkhor-sdd-reports/datasets-catalog.md`.

Approved starting set (license verified 2026-11-23): `aplycaebous/BanglaTLit`
(MIT), Dakshina `bn` (CC-BY-SA-4.0), `mehedihasanbijoy/BanglaSEC` (MIT),
`wikimedia/wikipedia` bn (CC-BY-SA-3.0/GFDL), `wordfreq` en+bn (Apache-2.0 code,
CC-BY-SA-4.0 data), `CodeMixBench/CodeMixBench` beneng (Apache-2.0),
`allenai/c4` bn sampled (ODC-BY), `openlanguagedata/flores_plus` bn
(CC-BY-SA-4.0, gated), and UD Bengali BRU/PUD (CC-BY-SA-4.0). Everything else
stays evaluation-only pending legal review.

Deliver:

1. `docs/design/datasets.md`: license tiers (`permissive`, `share-alike`,
   `non-commercial`/`unknown`), what may be shipped, what is evaluation-only,
   provenance/checksum rules, and the rule that datasets never enter git.
2. `crates/okkhor-train` dataset ingest:
   - `DatasetManifest` v1: `{schema, name, version, license, source, sha256,
     rows, languages, split, notes}`; refuses a manifest without a license.
   - `verify --manifest <path>`: checksum and row-count check, fails closed.
   - Small committed fixtures only: ≤ 2 MB total, synthetic or permissively
     licensed, used by tests and CI. Full corpora remain on the GPU host.
3. `crates/okkhor-learn` (additive):
   - `FeatureVectorV1` matching `docs/model-roadmap.md` §"Feature schema v1":
     `base_score`, `candidate_source`, `language`, `layout`, `prefix_len`,
     `word_len`, `user_word_count`, `pair_count`, `recency`,
     `acceptance_rate`, `correction_rate`, `bigram_score`, `phonetic_score`,
     `is_user_vocab`, `context_language`, `script_mix`. Stable order and
     explicit `SCHEMA_VERSION = 1`.
   - `extract_features(&SuggestionRequest, &Candidate, &SmritiSnapshot) -> Result<FeatureVectorV1, FeatureError>`
     with no I/O and no allocation beyond a bounded vector.
   - Determinism test: same inputs → byte-identical vector.
4. Replay format v1 (JSONL, one case per line):
   `{schema, case_id, language, layout, prefix, context, expected:[...], shown:[...], accepted:null|index, candidates:[...]}`.
   - Frozen synthetic replay set under `crates/okkhor-train/data/synthetic-replay.jsonl`,
     generated from the committed synthetic corpus and layout fixtures; at
     least 200 cases, committed, reproducible by a generator command.
   - A real-data evaluation slice (≤ 2 MB, permissive license only) may be
     committed later only after the catalog review; otherwise evaluation runs
     on the GPU host and the report carries the manifest checksum.
5. Evaluation metrics: top-1, top-5, MRR, acceptance rate, keystroke savings,
   and per-language/per-layout segments; p50/p95/p99 ranking latency. Output
   `--json` and a markdown report under git-ignored `bench-out/`.
6. Baseline report: Smriti and the engine on the replay set; record numbers in
   `docs/performance.md` as a labeled row (commit, date, profile, OS,
   dataset provenance caveat).
7. Remote tooling: `scripts/remote-dataset.ps1` (or `.sh`) that runs
   `ssh uiu-h200` with `hf download` into a project-space data directory,
   verifies the manifest, and runs ingestion there. Must not print tokens,
   hostnames, or usernames; must use `tmux` for long jobs.

Acceptance:

- `cargo test -p okkhor-learn -p okkhor-train` green; root checks green.
- Generator deterministic (same seed → same file, checksum recorded).
- No dataset larger than 2 MB committed; no user data, no legacy execution.
- The manifest verifier rejects a missing license, bad checksum, and short row
  count.

## Task 2 — Tier 1 logistic reranker (train + runtime + A/B)

Deliver:

1. `crates/okkhor-train` (offline, not shipped in the app):
   - Deterministic logistic regression trainer (plain Rust, no Python, no GPU):
     L2 regularization, fixed iteration count, seeded shuffle, feature
     standardization saved in the model.
   - `train --dataset <manifest> --out <model.json>`; train/validation split by
     `case_id` hash; refuse to train on < 200 cases.
   - Model JSON: `schema`, `name`, `version`, `feature_schema: "v1"`,
     `weights`, `bias`, `means`, `scales`, `trained_at`, `dataset_sha256`,
     `metrics {top1, top5, mrr, p99_ms}`, `notes`.
   - Training may run on the GPU host for large corpora, but the algorithm
     stays CPU-bound and deterministic; GPU is for data handling, not required.
2. `crates/okkhor-model` (shipped, `#![forbid(unsafe_code)]`):
   - Parse/validate the model JSON (finite weights, matching feature schema,
     bounded weight magnitude), checksum the file, and expose
     `LogisticReranker::score(&FeatureVectorV1) -> f32` with a deadline.
   - `HybridRanker` implementing `Ranker`: compute the baseline order, rescore
     within a deadline (`< 1 ms`), fall back to baseline on any error/expiry;
     blend `final = baseline + confidence * model_delta` where `confidence`
     grows with local evidence (contract in `docs/learning.md`).
   - Load only a bundled model by default. Reject unsigned downloaded models
     unless a public key is configured; checksum is mandatory in all cases.
3. Integration: engine/daemon rank path uses `HybridRanker` behind
   `--ranker hybrid|baseline` (default `baseline` until the A/B report is
   accepted). No new allocation per keystroke; preallocated feature buffer.
4. A/B report: baseline vs hybrid on the frozen replay set, with top-1/top-5
   deltas, p99, dataset licenses/provenance, and a clear statement of what the
   dataset can and cannot prove. If hybrid does not beat baseline, ship it
   disabled and record the negative result rather than tuning on the test set.
5. Tests: model parse/validation failures, checksum mismatch, deadline expiry
   fallback, determinism, no panic on NaN/Inf, feature-order mismatch
   rejection, and a golden score vector.

Acceptance:

- Hybrid p99 < 1 ms on the replay run; fallback proven by a test.
- Root checks green; `okkhor-train` excluded from release artifacts.
- No quality claim beyond the dataset's documented provenance.

## Task 3 — `okkhor-ai` worker, broker, and UI panel (text only)

Deliver:

1. `crates/okkhor-ai` (`#![forbid(unsafe_code)]`):
   - `AiProvider` trait, `AiRequest` (prompt, system, max_tokens, temperature,
     timeout), `AiResponse` (text, model, usage, latency), typed `AiError`.
   - `MockProvider` (deterministic), `DisabledProvider`.
   - `AiCache`: bounded LRU (default 64 entries, 256 KiB total), key =
     SHA-256(system + prompt + model + prompt_version), in-memory only; no text
     on disk.
   - `CircuitBreaker` (closed/open/half-open), single-flight per key, debounce
     helper, cancellation token.
   - `Policy`: explicit opt-in, rejects calls on the typing path, no
     keystroke/selection capture, max 1 in-flight, 15 s timeout, no text
     logging.
   - Optional `GeminiProvider` behind feature `http` using `reqwest`
     (`rustls-tls`, `json`), key from `OKKHOR_GEMINI_API_KEY`; never persisted
     or logged. Tests use a local fake HTTP server only.
2. `apps/okkhor-worker`: separate process, no window, bounded job queue (16),
   cancellation, health ping, and an IPC server on its own pipe/token passed by
   the daemon. The daemon proxies `ai.complete` after policy checks; the UI
   never talks to the worker directly.
3. Daemon: spawn/reap the worker, forward jobs, return typed errors, expose
   `ai.status` (enabled, provider, circuit state) without text.
4. UI: Settings → AI section with opt-in toggle, provider select, key presence
   indicator (set/unset only), and a "Try a rewrite" panel that requires an
   explicit click, shows a spinner, supports Cancel, and displays the typed
   error. The panel uses text the user pastes explicitly.
5. Docs: `docs/ai.md` with privacy, data flow, provider config, failure modes;
   `docs/security-privacy.md` updated.

Acceptance:

- No AI code linked into the daemon hot path; hook/ranking benchmarks unchanged
  beyond noise.
- Tests: cache eviction, key stability, breaker transitions, single-flight,
  cancellation, timeout, policy rejection, disabled provider, fake-server
  success/error mapping. No real network.
- Worker kill test: daemon keeps typing; next AI call returns `WorkerDown`.
