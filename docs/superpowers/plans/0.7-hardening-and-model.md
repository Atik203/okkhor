## 1. Why 0.7 exists

0.6 shipped the local dictionary, eight rows, English completions, and instant
state. It did **not** ship the dataset manifests, learned reranker, or AI worker
that were originally planned for 0.6. 0.7 closes that gap *and* hardens the
product against real Windows conditions before parity (0.8) and voice (0.9).

The release has two independent promises:

1. **Typing never regresses.** IME, RDP, elevated windows, DPI, sleep/resume,
   and process crashes are tested, not assumed.
2. **Intelligence stays off the key path.** The reranker is a sub-millisecond
   pure-Rust linear model with a hard deadline; AI is a separate opt-in process
   for explicit actions only.

## 2. Non-negotiable constraints

- No network, disk, model, UI wait, unbounded lock, or unbounded allocation on
  the keydown-to-character path (`AGENTS.md` §1).
- Local dictionary/Smriti always produce suggestions; a model miss or AI outage
  falls back silently and never stalls typing.
- No raw user text leaves the device. AI runs only on explicitly pasted text and
  only after opt-in.
- No text in logs, crash reports, telemetry, or cache keys stored on disk.
- `#![forbid(unsafe_code)]` in new non-Win32 crates; `unsafe` only in
  `okkhor-win` with a `// SAFETY:` comment.
- New crate or protocol change requires an ADR.
- CI runs offline with mocks/fixtures only.
- Heavy downloads, ingestion, and large-corpus training run **only** on
  `uiu-h200` under `tmux`/`screen`, inside the 200 GB project space, 18 GB VRAM
  slice, no hostnames/tokens in the repo or reports.
- Version stays `0.7.0`; a `0.6.1` patch ships first if owner QA finds defects.

## 3. Current code map

> Filled from the 0.7 touchpoint audit. See §3.1–§3.4.

### 3.1 Caret, popup, and typing path

Confirmed by the 0.7 caret audit:

- The low-level hook (`crates/okkhor-win/src/win32.rs:160-193,275-377`) only
  reads atomics and enqueues `KeyEvent`s. It never calls UI Automation.
- The daemon worker (`apps/okkhor-daemon/src/main.rs:1514,1777-1802`) drains
  keys and calls `refresh_popup` (`main.rs:703-744`) and
  `refresh_english_popup` (`main.rs:747-783`).
- `caret_anchor()` (`crates/okkhor-win/src/caret.rs:76-105`) is synchronous. It
  tries `GetGUIThreadInfo` (`caret.rs:110-147`), then UIA `TextPattern2` /
  `TextPattern` (`caret.rs:200-227`), then a mouse fallback
  (`caret.rs:375-393`). It always returns `Some`, so the daemon's `None`
  branches are unreachable.
- There is **no UIA timeout or deadline**. COM is initialized on every resolve
  (`caret.rs:170`). The only cache is the 500 ms focused-element cache
  (`caret.rs:149-162,263`).
- UIA cost is per key in Bangla (`main.rs:725`) and up to poll rate in English:
  `refresh_english_popup` runs unconditionally every loop (`main.rs:1716`), and
  `focused_element_is_password()` (`main.rs:1713`) adds another UIA traversal.
- Placement is `caret_anchor()` -> `CaretAnchor` -> `SuggestionPopup::
  show_candidates` -> `place_popup` (`popup.rs:350-380`, `caret.rs:321-348`).
- The popup HWND and its GDI state are created and owned by the daemon worker
  (`popup.rs:264-343,977-990`); only a `Copy` `CaretAnchor` may cross threads.
  `WM_DPICHANGED` already demonstrates re-placement from a stored anchor
  (`popup.rs:572-618`).
- Existing tests cover `place_popup` and pure layout (`caret.rs:422-458`,
  `popup.rs:1034-1121`). There is no test for tracker staleness, timeout,
  fallback, or "no UIA on the key path", and no popup/caret latency benchmark.

### 3.2 IPC, daemon lifecycle, settings, UI

Confirmed by the 0.7 IPC/UI audit:

- Protocol v1, 1 MiB frames, 5 s per-request deadline, 10 s client read
  deadline (`crates/okkhor-ipc/src/protocol.rs:16-26`). Additive methods keep
  v1; only a breaking shape change bumps `PROTOCOL_VERSION`
  (`transport.rs:221-225`).
- `Request::AiComplete(serde_json::Value)` already exists
  (`protocol.rs:204-205`) and is allowlisted (`:326`), but
  `transport.rs:286-288` returns `Unsupported` before any handler runs; the
  in-crate and daemon tests pin that behavior
  (`transport.rs:571`, `apps/okkhor-daemon/src/ipc.rs:1323-1341`).
- There is no AI response variant, no `ai.status`, and no cancel method.
- The daemon has **no child-process supervision**: `okkhor-engine` is
  in-process (`apps/okkhor-daemon/src/main.rs:1350-1356`), and UI launches are
  fire-and-forget (`ipc.rs:820-832`). 0.7 must add spawn/`try_wait`/reap for the
  worker; the 5 ms loop already gives a polling site (`main.rs:1514-1802`).
- `Settings.ai_enabled` exists (`crates/okkhor-ipc/src/settings.rs:187,244`);
  `SettingsPatch.ai_enabled` exists (`:655-656`); validation has no provider
  field (`:453-483`). Key presence should be reported by `ai.status`, never
  persisted.
- The UI has no textarea primitive; the AI card belongs between the Behavior
  card and the fonts `<details>` in `apps/okkhor-ui/src/pages/settings.tsx`
  (`:510-684`). The Tauri command list is registered at
  `apps/okkhor-ui/src-tauri/src/main.rs:958-984`.
- Tests that pin current behavior and must change: protocol golden fixtures
  (`protocol.rs:334-414,523-615`), transport Unsupported stub
  (`transport.rs:571`), daemon AI test (`ipc.rs:1323-1341`), settings defaults
  (`settings.rs:666-713`), UI fixtures (`src/test/settings-validation.test.ts`,
  `layout.test.tsx`), and error text (`src/lib/errors.ts:49-90`).
- Existing tests to extend: `slow_handler_times_out_and_connection_survives`
  (`transport.rs:752`) is the deadline harness; `ipc_roundtrip.rs:137-429` is
  the pipe sweep; `words.test.tsx` shows the mutation/panel pattern.

### 3.3 Ranking, features, trainer

Confirmed by the 0.7 ranking/model audit:

- `Ranker` is `crates/okkhor-core/src/candidate.rs:120-123`. `Suggestion`
  carries only text/language/score/source, no feature vector.
- Live path: daemon (`main.rs:1350-1356`) -> `DefaultEngine::Suggest`
  (`input_session.rs:427-437`) -> `InputSession::refresh`
  (`input_session.rs:322-335`) -> `SuggestionEngine::suggest`
  (`crates/okkhor-engine/src/suggest/mod.rs:129-164`) -> `Smriti::rank`
  (`crates/okkhor-learn/src/store.rs:530-558`).
- `SuggestionEngine` holds no ranker; it takes `&Smriti` directly
  (`mod.rs:129`). `CandidateEngine` is the separate 0.4 parity harness
  (`engine.rs:34-49,133-139`) used by golden/replay/bench.
- **English completions bypass `Ranker`**: `SuggestionEngine::suggest_english`
  scores and sorts directly (`mod.rs:168-201`), and the daemon calls
  `session.english_suggestions` (`main.rs:1695,1704`). A hybrid reranker affects
  Bangla candidates only unless a separate English path is added (out of 0.7).
- `Smriti::rank` scores, tie-breaks `(score desc, text asc)`, and truncates to
  `limit` (`store.rs:530-558`). There is a public per-candidate `score()`
  (`store.rs:343-351`) but **no bulk score API under one lock**. Centering
  requires all pool scores before truncation.
- `FeatureVectorV1`/`extract_features` are in `okkhor-train`
  (`features.rs:160-299`), have no serde derive, and replay cases store strings,
  not candidates (`replay.rs:48-65`). `accepted` indexes `shown`, not
  `candidates`; the trainer must map by text and count misses.
- The frozen synthetic replay has no learning snapshot, so learned features are
  near zero; a first model mostly learns base score/source/language/layout/
  lengths/context. Real quality needs a licensed corpus or synthetic learning
  events, both owner-gated.
- Baselines (`docs/performance.md:266-301`, 240 synthetic cases): engine top-1
  `0.6833`, top-5 `0.9667`, p99 `25,300 ns`; cold-start Smriti top-1 `0.2708`,
  top-5 `1.0` by construction. Any A/B must beat or explain these, with the
  synthetic-only caveat.

### WS1 — Datasets, manifests, and deterministic trainer (#100)

Goal: make training reproducible and auditable without shipping datasets.

Tasks:

1. **`DatasetManifest` v1** (`okkhor-train::manifest`):
   - fields per `docs/design/datasets.md` §Manifest v1 (`source`, `rows`);
   - reconcile the `1.0-release.md` sketch (`source_url`, `cases`,
     `created_at`) by treating those as later additive fields, not v1
     requirements;
   - `Split` enum: `train`, `validation`, `test`, `eval`;
   - validation: schema 1, non-blank `name`/`version`/`license`/`source`,
     exactly 64 lowercase hex SHA-256, non-empty `languages`, known split,
     bounded `notes`;
   - reject a missing or blank license, an "unknown" license, a checksum
     mismatch, and a row-count mismatch.
2. **`verify_manifest(path)`**:
   - read the referenced file, hash it, count rows, compare;
   - row counting rule: JSONL/text = non-empty lines; CSV/TSV = non-empty lines
     minus one header; declared in the manifest's `format` note or inferred from
     the extension, documented in `docs/design/datasets.md`;
   - typed errors, no panic, no network.
3. **Committed fixture:** synthetic JSONL plus manifest, total <= 2 MB, used by
   tests and CI.
4. **Deterministic logistic trainer** (`okkhor-train::train`):
   - reuse `FeatureVectorV1` and replay parsing;
   - binary label per candidate: `1` for the accepted candidate when
     `accepted` is present, otherwise `1` for `expected[0]`; all other
     candidates are `0`; skip and count cases where no candidate matches;
   - balance classes with `weight_pos = negatives / positives` so the ~5:1
     candidate ratio does not collapse the model to "always negative";
   - 80/20 split by `case_id` hash, not row order; refuse < 200 cases;
   - standardize using training-split means/scales only (saved in the model);
   - full-batch gradient descent: zero init, 500 iterations, learning rate
     `0.05`, L2 `1e-4`, deterministic float order, seeded shuffle of case order
     per iteration using the replay generator's SplitMix64;
   - model JSON: `schema`, `name`, `version`, `feature_schema: "v1"`,
     `weights`, `bias`, `means`, `scales`, `trained_at`, `dataset_sha256`,
     `metrics`, `notes`;
   - same seed + dataset => byte-identical JSON (no hash-map iteration, no
     wall-clock field in the deterministic core; `trained_at` is passed in or
     omitted from the byte-identity test).
5. **CLIs:** `okkhor-train-dataset --verify <manifest>` and
   `okkhor-train-fit --replay <path> --out <model.json> [--seed]`.
6. **Remote GPU path:** extend `scripts/remote-dataset.ps1` (or add it) to run
   downloads/ingestion/fit on `uiu-h200` under `tmux`, write a manifest, and
   copy back only manifests, checksums, and coefficients. Never print tokens or
   host identifiers.
7. **Docs:** update `docs/design/datasets.md` (row counting, fixture rule),
   `docs/design/replay.md` (training split), `docs/performance.md` (baseline).

Exit: verifier rejects malformed manifests; trainer determinism test passes;
no dataset > 2 MB committed.

### WS2 — `okkhor-model` hybrid reranker and A/B (#101)

Goal: add a learned reranker that is provably bounded and easy to disable.

Tasks:

1. **Feature-schema ownership (decision D1, ADR 0017).** Move
   `FeatureVectorV1` and `extract_features` into a small shipped crate
   `okkhor-features`; make `okkhor-train` re-export it. Rationale:
   `okkhor-model` must not link the offline trainer (engine/lang/transliterate
   dependencies).
2. **`okkhor-model` crate** (`#![forbid(unsafe_code)]`):
   - parse/validate model JSON: finite weights, `feature_schema == "v1"`,
     bounded magnitudes, checksum;
   - `LogisticReranker::score(&FeatureVectorV1) -> Result<f32, ModelError>`;
   - **no clock read**: Tier 1 uses a structural work bound (<= 64 candidates x
     16 features) instead of `Instant` inside the engine, preserving ADR 0011's
     no-wall-clock query rule;
   - reject unsigned downloaded models unless a public key is configured;
   - load only the bundled model by default.
3. **Hybrid blend (decision D2, ADR 0017).** Pin the formula in
   `docs/learning.md`:
   - center model scores across the candidate pool;
   - `final = baseline + confidence * centred_model_score * MODEL_WEIGHT`;
   - `confidence = 0.75 * (1 - exp(-evidence / 10))`, where `evidence =
     ln(1 + user_word_count) + ln(1 + pair_count) + 2 * acceptance_rate`;
   - confidence is **per candidate**, not a global user score;
   - confidence 0 reproduces baseline order exactly;
   - `MODEL_WEIGHT <= 1.0`, capped so the model cannot dominate a strong
     deterministic match.
4. **Ranker injection and `HybridRanker` (ADR 0019):**
   - add an additive `SuggestionEngine::suggest_with_ranker(&request,
     &dyn Ranker)` (or make `suggest` take `&dyn Ranker`); the daemon passes a
     `HybridRanker`, while the 0.4 `CandidateEngine` parity path keeps `Smriti`;
   - `HybridRanker` computes baseline scores for the **whole staged pool** via a
     new additive `Smriti::score_pool` (one read lock), centres the model
     scores, blends, sorts with the pinned `(score desc, text asc)` tie-break,
     then truncates to `limit`;
   - if the pool exceeds 64, any value is non-finite, or the model is absent,
     return the baseline order unchanged;
   - English completions stay on the existing static path in 0.7; the hybrid is
     Bangla-only and this is stated in the docs.
5. **Switch and loading:** daemon flag `--ranker hybrid|baseline`, default
   `baseline` until the A/B report is accepted; the bundled model ships as
   `crates/okkhor-model/assets/reranker-v1.json`, is embedded with
   `include_bytes!`, checksum-verified once at startup, and held in an `Arc`;
   no model disk read on the key path.
6. **A/B harness:** extend `okkhor-replay` with `--hybrid --model <path>` and
   report baseline vs hybrid top-1/top-5/MRR/p99, segmented by language/layout,
   with dataset licenses and checksums.
7. **Tests:** parse/validation, checksum mismatch, deadline fallback, NaN/Inf,
   feature-order mismatch, determinism, golden score vector, confidence-0
   identity.

Exit: hybrid p99 < 1 ms; fallback proven; default unchanged; no quality claim
beyond dataset provenance.

### WS3 — Opt-in AI worker and panel (#102)

Goal: ship an AI text action that is explicit, cancellable, and incapable of
delaying a keystroke. Process boundary: ADR 0018.

Tasks:

1. **`okkhor-ai` crate** (`#![forbid(unsafe_code)]`):
   - `AiProvider`, `AiRequest`, `AiResponse`, typed `AiError`;
   - `MockProvider`, `DisabledProvider`;
   - bounded in-memory LRU: 64 entries / 256 KiB, key =
     SHA-256(system + prompt + model + prompt version), never written to disk;
   - circuit breaker (closed/open/half-open), single-flight per key, debounce,
     cancellation token;
   - policy: explicit opt-in, reject calls originating on the typing path, max
     1 in-flight, 15 s timeout, no text logging;
   - live `OpenAiProvider` behind feature `http` (`reqwest` + `rustls-tls`),
     key from `OKKHOR_OPENAI_API_KEY`; model from `OKKHOR_AI_MODEL`, default
     `gpt-6-luna` (checked 2026-11-24: $0.10/$0.50 per 1M tokens; ~$0.0002 per
     short rewrite), with `gpt-6.1-terra` as the quality option ($1/$5); Gemini
     stays a future provider behind the same trait; tests use a local fake
     server.
2. **`apps/okkhor-worker`:** separate process, no window, bounded queue (16),
   cancellation token, health ping, own pipe/token. Pass the token through the
   child's **environment**, never argv; add a worker-token path helper beside
   `paths::token_path()`.
3. **IPC (async job, no 5 s violation):**
   - `ai.complete` validates and enqueues, then returns `{job_id}` immediately;
     it never holds the 5 s request deadline (`protocol.rs:26`).
   - Add `ai.poll` (pending/done/error + result), `ai.cancel`, and `ai.status`
     (enabled, provider, key set/unset, circuit state, active job).
   - Typed params/results with an explicit UTF-16 prompt cap (mirror
     `MAX_INSERT_UTF16` / `validate_insert_text`, `protocol.rs:273-278`).
   - Remove the `transport.rs:286-288` `Unsupported` early return; update the
     golden fixtures and the daemon/transport tests that pin it.
   - Additive methods keep protocol v1; errors carry codes only, never text.
4. **Daemon lifecycle:** spawn the worker lazily on the first request when
   `ai_enabled`, provider, and key presence allow it; reap with `try_wait()` in
   the 5 ms loop and bounded backoff; kill it before token removal on shutdown;
   proxy jobs after policy checks; expose `ai.status` without text. Add an
   `ai_enabled` atomic mirror or read `current_settings()` on `apply_seq`, and a
   dedicated log scope for worker failures.
5. **Settings and UI:** add `ai_provider` to `Settings`/`SettingsPatch`/
   `validate()` with a safe default, and update the exact-JSON defaults test
   (`settings.rs:666-713`). Settings → AI card between Behavior and fonts:
   opt-in, provider select, key set/unset badge from `ai.status`, privacy note,
   and a **Try a rewrite** panel (new textarea primitive): paste text, click,
   spinner, Cancel, typed error, result. No automatic insertion.
6. **Docs:** `docs/ai.md` (data flow, privacy, failure modes), update
   `docs/security-privacy.md` so AI prompts/responses are explicitly
   **memory-only, never persisted** in 0.7, note the memory-only cache in ADR
   0012, and update `docs/design/0.5-ui-contracts.md`, `docs/ui.md`, and
   `README.md` (which currently says `ai.complete` answers `Unsupported`).
7. **Model bake-off:** run 20 short Bangla/English rewrite samples through
   `gpt-6-luna` and `gpt-6.1-terra`; record quality, latency, and cost in
   `docs/ai.md`. Keep `gpt-6-luna` as the default unless Terra clearly wins on
   the sampled Bangla prose.

Exit: worker kill/timeout/outage never delays typing; no real network in CI;
cache and logs contain no prompt text.

## 8. Risks and mitigations

| Risk | Impact | Mitigation |
| --- | --- | --- |
| Scope is two releases in one | 0.7 slips | Ship 0.6.1 first; if needed cut 0.7.0 = hardening+model, 0.7.1 = AI |
| Feature-schema move breaks replay | silent metric drift | compatibility test: old and new extraction byte-identical on the frozen replay |
| Synthetic data cannot prove quality | misleading claims | keep the synthetic-only caveat; real-corpus A/B is owner-gated |
| Synthetic replay has no learning snapshot | learned features near zero; model mostly learns priors | state this in the report; add synthetic learning events or a licensed corpus before claiming personalization gains |
| English completions bypass `Ranker` | hybrid has no English effect | scope the hybrid to Bangla in 0.7; keep English static and document it |
| Clock-free engine rule | an in-engine deadline would violate ADR 0011 | structural work bound + daemon measurement; no `Instant` in engine/model |
| Model logit scale clashes with baseline | bad ordering | center scores, confidence-0 identity test, cap model weight |
| UIA hangs | popup lag or deadlock | capacity-1 latest-wins channel, timeout, fallback, no UIA on key path |
| 5 s IPC deadline vs 15 s AI | every AI call times out | async job: `ai.complete` enqueues and returns an id; `ai.poll`/`ai.cancel` carry the wait |
| Old UI + new AI error codes | generic "something went wrong" | ship UI and daemon together; new codes degrade to the generic message, never crash |
| GPU/token unavailable | dataset work blocked | trainer and verifier are local; GPU run is a separate owner-gated step |
| AI provider key absent | feature unusable | disabled provider is a first-class state; UI shows key unset |
| RDP/elevated access | matrix incomplete | record explicit failures; never claim untested rows |
| Owner real-key QA is the only real proof | false confidence | checklist sign-off is a release gate, not optional |
