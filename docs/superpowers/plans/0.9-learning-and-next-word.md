# 0.9 plan - local learning and next-word suggestions

Status: planned for 0.9.x after the 0.9.0 layout engine. Owner: Atik. This is
the "Apple-like" phase:
accurate, quiet, local, and explainable.

## Goals

- Learn the words and choices this user actually makes, in English and Bangla.
- Improve top-1/top-5 suggestions without sending text anywhere.
- Offer a small, non-intrusive next-word strip after a committed word.
- Keep the typing path unchanged: no disk, network, UI, AI, or unbounded lock.
- Make every learned signal visible, exportable, and resettable.

## Signals

| Signal | Source | Use |
| --- | --- | --- |
| `SuggestionShown` | popup paint (bounded, debounced) | denominator for acceptance |
| `SuggestionAccepted` | digit, click, or Tab/arrow commit | positive preference and roman pair |
| `Correction` | commit followed by backspace/retype | penalty for the replaced choice |
| `WordCommitted` | final injection | frequency, recency, vocabulary |
| `TransliterationCommitted` | existing path | roman -> Bangla pair |
| `NextWord` | next commit after a previous word | bigram/trigram next-word model |
| English word | English-mode commit | English vocabulary and prefix completion |
| App category | optional, off by default | weak context only after privacy review |

Events are emitted only on commit or explicit UI interaction, never per raw
keystroke. Latin fallback commits are not learned as Bangla pairs.

## Storage

- Reuse the existing DPAPI-encrypted `learning.bin` snapshot.
- Add bounded tables for `shown`, `accepted`, `corrections`, `bigrams`, and
  `trigrams`; keep the current 64-event batching and 30-second save cadence.
- Normalize NFC; cap word and pair lengths; never store window titles, raw
  keystrokes, passwords, or clipboard contents.
- Reset, export, and delete remain Settings actions.

## Ranking

The Smriti feature vector already has `acceptance_rate`,
`correction_penalty`, `context_score`, and `pair_frequency`. Wire them:

- `acceptance_rate = accepted / max(shown, 1)`;
- `correction_rate` rises only when a committed choice is replaced;
- `pair_frequency` ranks the user's roman -> Bangla choice;
- `context_score` uses the previous word(s), with a small bounded bigram term;
- recency keeps the 14-day half-life and the per-composition frozen clock.

Tune weights on replay, not intuition. Any weight change is recorded in the
relevant ADR or the model roadmap.

## Next-word UX

- After a commit with Space, show at most three next-word candidates in a
  subtle strip below the caret, separate from the transliteration list.
- Arrow/Tab accepts; typing any character dismisses it; never auto-insert.
- Hide in password fields, while paused, and when the confidence is below a
  conservative threshold.
- Do not show next-word suggestions in the middle of a word or after a
  correction until the next commit.

## English learning

- Learn English words the bundled dictionary does not contain, with frequency
  and recency.
- Prefix completions use the learned vocabulary first, then the dictionary.
- Corrections lower the wrong word's score without deleting it.
- Keep English and Bangla counters separate; a language switch is a context
  boundary.

## Evaluation

- Replay top-1/top-5, MRR, acceptance, and keystroke savings before/after.
- Add a real or licensed corpus A/B only after the owner approves the data.
- GPU (`uiu-h200`, H200 1g.18gb) is for a global prior or a larger reranker,
  never for the per-user local adapter. No raw user text leaves the device.
- A quality claim requires a measured improvement over baseline, not a demo.

## Milestones

1. `0.9.0` - wire shown/accepted/corrected events; learn accepted roman pairs
   and English vocabulary; add reset/export; replay metrics.
2. `0.9.1` - next-word strip from local bigrams; confidence threshold and
   password suppression.
3. `0.9.2` - corpus A/B and, only if it wins, a GPU-trained global prior.
4. `0.9.x` - polish, accessibility, and the Apple-like quiet motion pass.

## Non-goals for 0.9

- cloud training by default;
- storing raw documents or full sentences;
- auto-inserting next words;
- inline preedit and punctuation commit (separate ADR and owner QA).
