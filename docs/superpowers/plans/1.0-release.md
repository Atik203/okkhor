# 1.0 — Global prior, packaging, parity, release

Plan of record for milestone 1.0. Prerequisites: 0.5, 0.6 (suggestion data and
English completions), 0.7 (hardening, Tier 1 reranker, AI text), 0.8 parity,
and 0.9 voice merged with green `main` CI. Binding rules: `AGENTS.md`,
`docs/design/datasets.md`, `docs/release.md`, `docs/security-privacy.md`,
`docs/model-roadmap.md`.

## Global constraints

- No release claim without evidence. Every row is either measured, automated,
  or marked `not run` with the reason.
- Raw user text never leaves the device. Training data is licensed or
  synthetic; a dataset manifest records provenance and checksums.
- The model is optional. If it fails to load or misses its deadline, the
  deterministic ranker runs and typing is unaffected.
- Artifacts are built only from a tagged commit, reproducibly.
- Signing keys and certificates are never committed. Unsigned artifacts are
  labeled `UNSIGNED` in the manifest, release notes, and About screen.
- Owner-gated items (signing certificate, real-desktop manual QA, provider
  keys, licensed corpus) are escalated once, recorded, and never faked.

## Merge order

`1 → 2 → 3 → 4 → 5 → 6`. Tasks 3 (packaging) and 5 (QA) can start once 1 and 2
are merged. Tag only after Task 6's gate table is complete.

## Task 1 — Global prior pipeline, model package, local adapter

Deliver:

1. `okkhor-train`:
   - dataset manifest schema v1: `{schema, name, version, license, source_url,
     sha256, cases, languages, created_at, notes}`; refuse a dataset without a
     license field.
   - `train --dataset <jsonl> --out <model.json>` reusing Task 0.6's trainer;
     deterministic, seeded, train/validation by `case_id` hash.
   - Bootstrap dataset: synthetic cases generated from the bundled
     transliteration rules, layout key tables, and synthetic dictionary
     fixtures. Explicitly labeled `synthetic-bootstrap-v1`; **no** claim of
     real-world Bangla/English quality.
   - If a licensed corpus is supplied via `--dataset`, the same command trains
     the global prior; the owner supplies the corpus or approves the catalog
     entry. No corpus is committed. Downloads and ingestion happen only on the
     cloud GPU per `docs/design/datasets.md`.
2. Local adapter:
   - Extend the hybrid blend with a local component trained from
     `SmritiSnapshot` aggregates (counts/recency/acceptance/correction) using
     the same feature schema. Local training runs on-device in a maintenance
     task, is bounded (< 50 ms, off the keystroke path), and is optional.
   - `confidence(n)` curve documented and tested; a user with no history gets
     exactly the global prior.
3. Model package: `model.json` + `manifest.json` with `sha256`, `signature`
   (optional), `feature_schema`, `dataset_sha256`, metrics, and `trained_at`.
   Bundled model ships in the installer; downloaded models require a configured
   Ed25519 public key and a valid signature, otherwise they are rejected.
   Implement verification with `ed25519-dalek` (small, audited) or a minimal
   verifier; no custom crypto.
4. Evaluation report: global, local, and blended on the frozen synthetic
   replay; segments by language/layout; p99 < 1 ms; negative results recorded.
5. Feature flag: `--ranker hybrid|baseline`, default `baseline`; the UI exposes
   "Personal ranking (beta)" with an instant fallback switch.
6. Docs: `docs/model.md` (data, training, packaging, rollout, rollback),
   `docs/learning.md` blend contract, `docs/security-privacy.md` model/data
   statement, `docs/model-roadmap.md` status update.

Acceptance:

- Reproducible training from a clean checkout and the committed synthetic
  dataset (same checksums).
- Tests: manifest/license rejection, checksum mismatch, signature
  accept/reject, blend confidence bounds, local-training bounds, fallback.
- No quality claim beyond the synthetic report; real-corpus training remains
  owner-gated and documented.

## Task 2 — Settings/data schema freeze, migration, backup and rollback

Deliver:

1. Freeze data schemas for 1.0: settings v1, words v1, learning snapshot v1,
   model manifest v1. A schema change after 1.0 requires a migration and a
   minor-version bump.
2. Migration tool (`okkhor-daemon migrate --from <dir> --to <dir>`):
   - 0.x settings/words/learning → 1.0, with a report of imported, skipped, and
     unsupported items;
   - refuses legacy Python pickle; documents the supported JSON/export inputs;
   - idempotent, dry-run mode, and a backup copy before writing.
3. Backup/restore/delete commands for user data, with confirmation and no
   network.
4. Rollback test: install 1.0 layout in a temp home, write data, restore a
   pre-migration backup, verify the app still starts with defaults and reports
   the skipped data honestly.
5. Docs: `docs/migration.md`, `docs/release.md` update, `docs/recovery.md`.

Acceptance:

- Migration round-trip and rollback tests green.
- No data loss without an explicit report; corrupt input fails closed.

## Task 3 — Build, installer, portable ZIP, SBOM

Deliver:

1. `scripts/build-release.ps1`:
   - `cargo build --release --locked` for daemon, worker, and Tauri UI;
   - stage `dist/Okkhor-<version>/` with `okkhor-daemon.exe`,
     `okkhor-ui.exe`, `okkhor-worker.exe`, assets, licenses, and docs;
   - produce `Okkhor-<version>-win64-portable.zip` and `SHA256SUMS.txt`.
2. Installer:
   - Tauri NSIS bundle with sidecars (`externalBin`) for daemon and worker;
   - Start Menu shortcut to the UI, optional "Start Okkhor at login" checkbox
     wired to the existing autostart module (not the installer's own Run key);
   - uninstall removes binaries and shortcuts but **never** user data without
     an explicit checkbox; documents data locations;
   - per-user install by default (no elevation), machine-wide optional.
3. `Okkhor-<version>.sbom.json` from `cargo metadata` (CycloneDX-like minimal
   schema) plus npm production dependencies; `THIRD_PARTY_LICENSES.md`
   generated from crate/npm metadata with a manual review pass.
4. Version resources: `1.0.0` in workspace, Tauri config, Windows
   `VERSIONINFO`, About screen, and `--version` output. One source of truth:
   the workspace version with a test asserting the others match.
5. Signing hooks: `scripts/sign.ps1` using `signtool` and env
   `OKKHOR_SIGN_CERT`/`OKKHOR_SIGN_PASSWORD`; when absent, artifacts are
   labeled `UNSIGNED` and the script exits 0 with a warning. Never commit
   certificates.
6. Reproducibility: record toolchain, target, and commit in
   `dist/Okkhor-<version>/BUILD-INFO.json`; rebuild and compare hashes for the
   Rust binaries where the toolchain allows.

Acceptance:

- A clean `scripts/build-release.ps1` run produces the ZIP, installer, SBOM,
  checksums, and build info.
- Installer installs, launches the UI, starts the daemon, and uninstalls
  cleanly on this machine in a temp profile, or the exact failure is reported.
- No secret in any artifact.

## Task 4 — Update manifest, verification, rollback

Deliver:

1. `latest.json` schema: version, channel, min_version, url, sha256, size,
   signature, notes_url, published_at.
2. `scripts/make-manifest.ps1` and `scripts/verify-manifest.ps1`; Ed25519
   sign/verify with a public key injected at build time (`OKKHOR_UPDATE_PUBKEY`
   env or config); unsigned manifests are rejected by the app.
3. `crates/okkhor-update` (small, pure Rust): parse/validate manifest, compare
   versions, verify checksum/signature, staged download to a temp file,
   atomic swap on next start, rollback to the previous binary on failure.
   Update checks are user-initiated in 1.0 (no background network calls).
4. Tests: schema rejection, bad signature, downgrade refusal, interrupted
   download, rollback, no network in tests.
5. Docs: `docs/update.md`, release process integration.

Acceptance:

- Update flow proven end-to-end locally with a self-signed test key generated
  in a temp dir (not committed) and a local file URL.
- With no public key configured, the UI says "Updates are not configured" and
  performs no network request.

## Task 5 — Parity, security, performance, and QA gates

Deliver:

1. `docs/parity.md`: feature matrix against the legacy app (input, layouts,
   dictionaries, suggestions, learning, popup, UI, speech, AI, settings,
   migration), each row `done`, `partial`, `not implemented`, or `owner-gated`,
   with evidence links. No silent gaps.
2. Security review: `unsafe` inventory with SAFETY comments; IPC ACL/token
   test; DPAPI tamper test; log redaction test; dependency license audit;
   secret scan (GitGuardian already runs); threat-model re-check against
   `docs/security-privacy.md`.
3. Performance gate on this machine: hook p99, inject p99, candidate p99,
   hybrid rerank p99, popup show, UI cold start, IPC round-trip; compare to
   `docs/performance.md` budgets; record shared-desktop caveats.
4. Automated QA in `scripts/qa-1.0.ps1`: daemon self-check, IPC smoke, settings
   round-trip, words import/export, model load/fallback, worker down, installer
   presence, hash verification.
5. Manual QA checklist for the owner: clean Windows 11 VM, Notepad/browser/
   Electron/Office/elevated/RDP, DPI 100–200%, multi-monitor, IME on/off, sleep
   resume, 10k-key stress, uninstall/reinstall, upgrade from 0.2.0, speech
   opt-in/out and microphone denial. Rows marked `not run` until executed.
6. File and close issues honestly: close only what the evidence supports; keep
   #2/#5/#6/#7/#8 open if they remain unexecuted, or split them into
   `owner-gated` with a clear checkbox list.

Acceptance:

- Every gate row has evidence or an explicit owner-gated status.
- No P0/P1 privacy or security issue open.
- No performance regression beyond documented budgets.

## Task 6 — Release 1.0.0

Deliver:

1. Version bump to `1.0.0`; `CHANGELOG.md` covering 0.2 → 1.0 in user terms;
   release notes with known limitations (unsigned artifacts if applicable,
   synthetic-only model quality, loopback capture gap, unexecuted manual QA).
2. Tag `v1.0.0` on the release commit; GitHub release with artifacts,
   `SHA256SUMS.txt`, SBOM, build info, and the parity table.
3. Post-release verification: download the artifact, verify hashes, install,
   run `qa-1.0.ps1`, confirm typing and UI, uninstall.
4. Archive the sprint ledger and reports; delete merged worktrees; confirm
   `main` CI green on the tagged commit.
5. Write `docs/releases/1.0.0.md` with the gate table and every exception that
   was accepted, including who accepted it.

Acceptance:

- Tag exists, artifacts downloadable, hashes match, and the release notes match
  what was actually verified.
- If the owner-gated signing certificate is still absent, the release is
  published as `1.0.0` **UNSIGNED** with the limitation stated in the first
  paragraph, or held as `v1.0.0-rc` if the owner prefers. This decision is
  recorded before tagging, not after.
