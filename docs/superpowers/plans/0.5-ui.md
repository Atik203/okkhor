# 0.5 — Settings UI, on-screen keyboard, word manager

Plan of record for milestone 0.5. Binding contracts:
[`docs/design/0.5-ui-contracts.md`](../../design/0.5-ui-contracts.md) and
[ADR 0012](../../adr/0012-ui-ipc-and-settings.md). Read both before Task 1.

## Global constraints

- Typing is sacred: no UI or IPC code may be reachable from the hook or input
  worker hot path. No per-keystroke IPC.
- `#![forbid(unsafe_code)]` for `okkhor-ipc` and `okkhor-ui` logic. Any
  `unsafe` stays in `okkhor-win`, with a `// SAFETY:` comment.
- No new secrets, user text in logs, or proprietary assets.
- No cloud calls in 0.5. AI/speech fields are persisted but inert.
- Tauri UI is a separate process; a UI crash must not stop typing.
- Root workspace checks must stay green and fast: `apps/okkhor-ui` is excluded
  from the root workspace and has its own Node/Rust checks.
- Every task: Conventional Commit, tests for new behavior, docs updated in the
  same change, no subagents, no pushes.
- Do not rename existing public APIs. Additive changes only unless the contract
  says otherwise.

## Merge order

`1 → 2 → 3 → 4 → 5 → 6`. Tasks 1 and 2 may run in parallel in isolated
worktrees; the lead resolves `Cargo.toml` conflicts. Tasks 4–5 depend on the
merged protocol types from Task 1.

## Task 1 — `okkhor-ipc` protocol, framing, auth, transport

Scope: new crate `crates/okkhor-ipc`.

Deliver:

1. `src/lib.rs` exposing modules `protocol`, `frame`, `auth`, `transport`,
   `error`, `settings`, `words`.
2. `protocol.rs`:
   - `PROTOCOL_VERSION: u16 = 1`, `MAX_FRAME_BYTES: usize = 1_048_576`,
     `MAX_CLIENTS: usize = 4`.
   - serde types for `Hello`, `ServerHello`, `Request`, `Response`, `Status`,
     `ErrorCode`, `ErrorBody` exactly matching contract §4.
   - `Request` variants for every 0.5 method in contract §4; `ai.complete`
     returns `ErrorCode::Unsupported`.
3. `frame.rs`: `write_frame`/`read_frame` over `tokio::io::{AsyncRead,
   AsyncWrite}` with u32 LE length, rejecting length 0 and > 1 MiB, and a
   `FrameError` for truncation/timeout.
4. `auth.rs`: 32-byte CSPRNG token (`getrandom` or `ring`-free via
   `windows::Win32::Security::Cryptography::BCryptGenRandom` is not available
   in this crate; use the `getrandom` crate), hex encode/decode, constant-time
   compare, token file path resolution under `%LOCALAPPDATA%\Okkhor\runtime\`,
   read/write with create-new semantics and 0600-equivalent intent.
5. `transport.rs`: tokio named-pipe server and client.
   - Server enforces the SDDL from ADR 0012
     (`ConvertStringSecurityDescriptorToSecurityDescriptorW`, owner + system).
     If the unsafe call is unavoidable, isolate it in one module with SAFETY
     comments; the rest of the crate stays unsafe-free.
   - `first_pipe_instance(true)`, one instance per client, max 4, graceful
     shutdown.
   - Hello handshake with protocol check and constant-time token compare;
     failures close the connection and increment a bounded counter.
   - Per-request deadline 5 s, server read timeout 10 s.
   - Client helper used by the daemon tests and the Tauri Rust side.
6. `settings.rs`: exact `Settings`, `SettingsPatch`, defaults, merge, and
   validation/clamping per contract §2, with unit tests for every bound
   (NaN, font scale, popup items, hotkey, unknown layout, unknown schema).
7. `words.rs`: `Word`, `WordsFile`, CSV parse/serialize with header
   `roman,output,language`, JSON import, validation per contract §3, caps and
   duplicate detection. CSV must handle quoted fields, CRLF, and a UTF-8 BOM;
   reject control characters in fields.
8. Tests: framing bounds and truncation, oversized frame, bad token, wrong
   protocol version, unknown method, settings validation, CSV/JSON round-trip,
   duplicate detection, import cap, token file round-trip.
9. Dependency justification in the PR: `tokio` (named pipes + timeouts) and
   `getrandom` (CSPRNG). No other runtime deps.

Acceptance:

- `cargo test -p okkhor-ipc` green; root fmt/clippy/test green.
- No network, no legacy access, no user data.
- Protocol types serialize to the JSON shapes in contract §4 (assert one golden
  JSON fixture per request kind).

Dependencies for later tasks: all protocol/settings/word types above.

## Task 2 — DPAPI protector, encrypted repository, settings and word stores

Scope: `crates/okkhor-win/src/dpapi.rs`, `crates/okkhor-storage`, daemon store
modules.

Deliver:

1. `okkhor-win::dpapi`:
   - `protect(plaintext: &[u8], entropy: &[u8]) -> Result<Vec<u8>, DpapiError>`
     and `unprotect` using `CryptProtectData`/`CryptUnprotectData`
     (`CRYPTPROTECT_UI_FORBIDDEN`, current-user scope).
   - `LocalFree` of the output blob exactly once; every unsafe block has a
     SAFETY comment naming the pointer/length invariant.
   - Typed errors (`TooLarge`, `ProtectFailed(io::Error)`, `UnprotectFailed`),
     no plaintext in error messages.
   - Windows-only module, re-exported on Windows; non-Windows returns
     `Unsupported` so the workspace still builds elsewhere.
   - Tests: round-trip, tamper rejection (flip a byte), empty input, 1 MiB
     input, distinct entropy fails.
2. `okkhor-storage`:
   - `Protector` trait (`protect`/`unprotect`).
   - `EncryptedJsonRepository<T>` with atomic write (temp file in the same
     directory + `rename`), DPAPI envelope `OKE1` magic + version + ciphertext,
     size cap 8 MiB, schema validation, `load` returning `NotFound` vs
     `Corrupt` distinctly.
   - Tests with a fake XOR protector for determinism plus one DPAPI-gated test.
3. Daemon stores (`apps/okkhor-daemon/src/settings_store.rs`,
   `words_store.rs`):
   - `SettingsStore` loads/validates/writes `settings.json`, defaults on
     missing, `UnsupportedSchema` on other versions, atomic replace, and
     exposes `update(patch) -> Result<Settings>`.
   - `WordsStore` loads/saves `words.bin` through the encrypted repository,
     assigns ids, enforces cap/duplicates, supports search/pagination,
     add/remove/import/export.
   - Unit tests for defaults, schema rejection, clamping, id assignment,
     duplicate rejection, cap, search, import/export.
4. Surface the paths through a small `paths` module
   (`%LOCALAPPDATA%\Okkhor\{settings.json,data\words.bin,runtime\ipc.token}`)
   with `OKKHOR_DATA_HOME` override for tests only (document it).
5. Docs: `docs/security-privacy.md` gains the DPAPI implementation note and the
   exact files; `docs/release.md` lists data locations for migration.

Acceptance:

- Root checks green; new tests green.
- No plaintext user words in logs, temp files, or error messages.
- Corrupt/tampered files fail closed (no partial load, no overwrite of the
  original before a successful write).

## Task 3 — Daemon IPC server and handlers

Scope: `apps/okkhor-daemon`.

Deliver:

1. Start the IPC server on a dedicated thread/runtime when `daemon` mode runs;
   publish then rotate `runtime/ipc.token`; remove the token on clean shutdown.
2. Handlers exactly per contract §4:
   - `status` from live daemon state (pause, layout, version, word count,
     autostart);
   - `settings.get/update` through `SettingsStore`; applying changes emits
     daemon actions: capture pause, input mode (Bangla/English), output encoding
     (Unicode/Bijoy), toggle/pause hotkeys with conflict fallback, autostart
     on/off (existing module), popup enable/max-items (popup module), learning
     enable flag; font choices are validated and applied. If a field cannot be
     applied live, return `Applied::Deferred` with a typed field instead of
     lying;
   - `layouts.list` from `okkhor-lang` known layouts (code + display name);
   - `words.*` through `WordsStore`;
   - `text.insert` through the existing injector, capped and only when the
     UI is authenticated; rate-limit to 20 inserts/s;
   - `capture.set` toggles the existing pause state and updates the tray.
3. Tray `Settings` action launches `okkhor-ui.exe` next to the daemon (or via
   `OKKHOR_UI_PATH` for dev); if missing, show a tray balloon "UI not
   installed" and log a code, never a path containing a user name.
4. Logging: only allowlisted event codes (`ipc.start`, `ipc.client`,
   `ipc.error`, `settings.update`, `words.import`, `ui.launch`); no params, no
   text. Extend the existing logger with the new events.
5. Integration tests (`apps/okkhor-daemon/tests/ipc_roundtrip.rs`): start the
   server on a temp data home with a test token, connect, handshake, status,
   settings round-trip, word add/list/remove, bad token rejection, oversized
   frame rejection. No hook installation in tests.
6. Docs: daemon CLI help gains `--no-ipc` (tests/CI) and `--ui`; README gains
   the "open settings" path.

Acceptance:

- Root checks green; integration tests green on Windows.
- Typing path unchanged: no new allocation or lock on the hook thread; bench
  smoke still passes.
- Killing the UI mid-request leaves the daemon healthy (covered by a test that
  drops the client).

   - **Tailwind CSS v4** for styling, **shadcn/ui** components on Radix
     primitives, **lucide-react** icons, **sonner** toasts,
     **@tanstack/react-query** for daemon queries/caching,

     `clsx`/`tailwind-merge`/`class-variance-authority` as utilities.

   - Route-level code splitting; initial JS budget ≤ 350 KB gzip.
   - Theme via CSS variables; light/dark/system and accent presets.
2. `src-tauri`:
   - empty `[workspace]` table, Tauri 2 config, app id `app.okkhor.ui`,
     window 960×640, min 720×520, title "Okkhor Settings";
   - Rust commands `ipc_status`, `ipc_get_settings`, `ipc_update_settings`,
     `ipc_list_layouts`, `ipc_insert_text`, `ipc_set_paused` backed by
     `okkhor-ipc` client; typed errors surfaced to JS;
   - no `unwrap` on user paths; token read failure maps to a typed error.
3. React:
   - app shell with sidebar routes `/`, `/settings`, `/keyboard`, `/words`,
     `/about`; unknown route → status;
   - status page: daemon version, paused toggle, mode (Bangla/English),
     language/layout, output encoding (Unicode/Bijoy), word count, autostart,

4. Accessibility: landmarks, labelled controls, focus ring, Escape closes
   dialogs, Enter submits, no color-only status, `prefers-reduced-motion`.
5. Tests: Vitest + React Testing Library for validation mirrors, settings
   reducer, route guard, theme application, and keyboard interaction; Rust unit
   test for the client error mapping.
6. CI: add a `ui` job in `.github/workflows/ci.yml` running `npm ci`,
   `npm run build`, `npm test`, and `cargo test` in `src-tauri`. Cache npm and

7. Docs: `docs/ui.md` with architecture, routes, build/dev commands, and the

## Task 5 — On-screen keyboard and word manager

Scope: `apps/okkhor-ui/src/features/{keyboard,words}` plus daemon support.

Deliver:

1. Keyboard page:
   - layout selector from `layouts.list`; grid rendered from a static,
     contract-approved key table per known layout (avro, national, probhat,
     bijoy, banglish, khipro). If a layout has no key table yet, show an
     explicit "layout table not bundled" state — do not invent mappings.
   - click inserts via `text.insert`; modifier keys (Shift) affect the visible
     grid; no auto-repeat; disabled when daemon absent.
   - groups: function row, Bengali letters, vowel signs, digits, symbols;
     drag-and-drop reordering persisted in `localStorage` (non-sensitive);
     favorites and recents persisted through the word store? No — favorites are
     settings-adjacent; store in `localStorage` with a versioned schema.
   - emoji search over a small bundled list (no network), insertion via
     `text.insert`.
2. Words page:
   - paginated table (50 default), search, add form (roman/output/language),
     remove with confirm dialog, import CSV/JSON with preview (first 20 rows)
     and counts, export CSV/JSON downloads generated client-side from
     `words.export`;
   - duplicate and validation errors shown inline; never echo other words.
3. Tests: keyboard grid reducer (groups, shift, disabled state), emoji search,
   word form validation, pagination, import preview parsing.
4. Docs: `docs/ui.md` gains keyboard and word-manager sections; `docs/qa/`
   checklist rows for click-insert, layouts, import/export, and no-focus-theft.

Acceptance:

- Vitest green; build green.
- Insert respects the 512-unit cap and reports the daemon error verbatim by
  code.
- No keystroke logging, no network, no persisted raw text in `localStorage`.

## Task 5b — Quick control bar (native)

Scope: `crates/okkhor-win/src/quickbar.rs`, daemon wiring.

Deliver:

1. Native `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW | WS_EX_TOPMOST` popup window,
   no taskbar entry, 90% opacity, 8 px corners, system light/dark + accent.
2. Buttons: mode chip (বাংলা/EN), encoding chip (ইউনিকোড/বিজয়), pause, OSK,
   settings, collapse. No microphone until 0.9.
3. Non-activating clicks; drag from background; snap to monitor edges; remember

   from settings/status.
5. Never displays user text; no logging of text.
6. Tests for state/layout math (hit boxes, snap, DPI scaling, collapse), plus an
   ignored manual visual smoke test.
7. Docs: `docs/ui.md` quick-bar section; ADR 0014 updated if behavior changes.

Acceptance:

  window.
- Position/visibility survive restart; multi-monitor and 100–200% DPI pass
  manual smoke.
- No text or keystrokes in logs.
