# 0.10.0 — Kontho-feel typing, learning, and model training plan

Status: planned. Owner: Atik. This plan implements the owner's request that
0.10.0 feel like Kontho in daily use and that personal and global learning be
completed in phases.

Evidence base:

- `docs/superpowers/analysis/0.10-suggestions-and-data.md` — WTR1 is fully
  specified; no frequency field exists in either reference; exact Kontho
  trie scoring; our index loses 15.7 % of pairs; baseline golden top1 92.9 %,
  top5 100 %.
- The Kontho inline-preedit static/runtime analysis, being written under
  `docs/superpowers/analysis/`; Phase 1 is refined from it before coding.
- `docs/adr/0021-fixed-layout-engine.md`, `docs/learning.md`,
  `docs/model-roadmap.md`, `AGENTS.md`.

Baseline release for this plan: **0.9.3**.

## Non-negotiable constraints

- Typing never waits on disk, network, UI, AI, or an unbounded lock.
- No raw user text leaves the device without an explicit opt-in action.
- Custom words stay local by default. A global contribution must be opt-in,
  aggregate, differential-privacy protected, and documented.
- No model is enabled by default until a frozen A/B beats the baseline and the
  p99 budget holds.
- `uiu-h200` (H200 1g.18gb) is used only for a measured Tier 2 candidate, never
  for the per-user adapter.

## Phase 1 — Kontho-feel typing (inline preedit)

Goal: the document shows Bangla evolving per keystroke, Backspace walks it back
in the same order, and Up/Down change the word live.

### 1.1 ADR 0022 — inline preedit state machine

- Record: swallow letters in Bangla phonetic mode; keep roman buffer plus the
  last painted preedit; per-key replacement; failure re-emit; Esc revert.
- Define exact state: `roman_buffer`, `last_preedit`, `last_preedit_len`,
  `composition_id`, `frozen_rank_ms`.
- Document undo-history trade-off and the on/off setting.

### 1.2 Inline preedit engine

- Hook swallows letters in Bangla phonetic mode (same path as fixed layouts).
- On each letter: compute best candidate, build one batch that erases the
  previous preedit length and inserts the new Bangla preedit.
- No preedit until the first dictionary-backed candidate exists; raw Latin is
  not injected.
- Update the popup rows and selection from the same candidate request.

### 1.3 Backspace walk-back

- Backspace removes one roman character, recomputes from the prefix cache, and
  replaces the preedit with the shorter form.
- At an empty buffer, the last preedit is erased and the composition ends.
- Focus change, pause, mode switch, layout switch: cancel and leave the last
  preedit in place, never erase another window.

### 1.4 Live Up/Down, Tab, Space, Esc

- Up/Down replace the current document word with the highlighted row, using the
  previous preview length as the erase count (English already does this; extend
  the same state machine to Bangla).
- Tab and Space finalize the current preedit; Tab adds no space, Space adds one.
- Esc reverts the preedit to the raw roman buffer.
- Held keys and overlapping swallowed keys use the per-key swallow flags.

### 1.5 Punctuation and digit choices (Kontho style)

- `.` shows `।` as row 1 and `.` as row 2; default commits `।`, row 2 commits a
  literal dot so `1.2` is typeable.
- Digits show the Bangla numeral as row 1 and the ASCII numeral as row 2;
  default commits Bangla.
- The choice card uses the same non-activating popup and selection keys; it
  never blocks the next character.

### 1.6 Popup feel

- Keep the current in-place card, 30 ms coalescing, sticky width and cached
  widths.
- Add per-layout/per-mode QA for no flicker on every key and Backspace.
- Keep placement just below and slightly left of the caret.

### 1.7 Toggle and QA

- Settings: `Inline Bangla preedit` (default on) so a user can fall back to
  commit-on-Space instantly.
- Real-key rows: Notepad, Word, Chrome, VS Code, password field, IME on,
  elevated target, RDP, multi-monitor, undo after commit.
- Exit: no lost keystroke, no wrong-window erase, top5 unchanged, p99 within
  budget.

## Phase 2 — Index v2 and full dictionary import (A1–A3)

### 2.1 A1 — reviewed WTR1 exporter v2

- Bounds-checked parser of the documented WTR1 layout.
- `filter_dic` → NFC before validation; keep all `m` targets, not only one.
- New ROMAN record: `u32 key_off | u16 key_len | u8 preferred_rank |
  u16 out_len | u32 out_off`; `OKS1 version = 2`.

- Import zero user recents; record their counts as provenance only.

## Phase 3 — Ranking and frequency (B1–B4)

Constraint: no `FeatureVectorV1` change in 0.10.0. Dictionary signals fold into
`base_score`; the shipped logistic model stays valid.

- **B1** deterministic preferred-rank epsilon tie-break.
- **B2** `stage_typo`: transposition at 0.86/0.90, length 3–11, must exist in
  the dictionary, pool capped at 16.
- **B3** bounded preferred-rank weight (−0.015/step, cap −0.06) behind a flag;
  keep exploration slots 3–5 within one score step.
- **B4** optional compound-split strip, never displacing a single word.
- Frequency prior: replace `wordfreq`-only BN popularity with a licensed
  Wikimedia-derived zipf prior (Phase 5 D3), not before it is measured.

Gates: golden top1 ≥94.0 %, top5 =100 %, replay MRR ≥ baseline −0.005,
ranking p99 ≤2 ms, candidate p99 ≤3 ms.

## Phase 4 — Personal learning (C1–C4) and next-word

- **C1** emit `SuggestionShown` / `SuggestionAccepted` with one event per
  `(request_id, position)`, deduped per composition.
- **C2** `Correction` on same-slot retype, plus `NextWordAccepted`.
- **C3** byte budgets: words 2.4 MB, pairs 8 MB, bigrams 8 MB, snapshot ≤24 MB;
  compact to 70 % in `maintain()`.
- **C4** privacy tests: no word bytes in logs, password/pause suppression,
  export/delete, no window titles.
- Next-word strip: local bigrams only, confidence threshold, never auto-insert,
  hidden in password fields.

Exit: acceptance rate >0 in a scripted session; taught corrections appear next
time; snapshot bounded after a 30-day replay.

## Phase 5 — Data pipeline and global prior (D1–D3)

- **D1** replay schema 2 with shown position, composed time, corrected-from;
  v1 still parses.
- **D2** frozen licensed A/B set of ≥1,000 cases; publish the gate table.
- **D3** BN frequency prior from Wikimedia `bn` counts (CC-BY-SA, derived
  counts only, attribution + legal review); target ≥120,000 BN words covered.
- Roman pairs: BanglaTLit (MIT) + Dakshina `bn` (CC-BY-SA) + synthetic
  romanisation through our own layouts.
- Every artifact: manifest, checksum, row count, train/eval split by case hash.

## Phase 6 — Global model training (phased)

The honest current state: **no global model has been trained on large
datasets.** These phases do that, with gates.

### 6.1 Feature schema v2 + ADR

Add shown/accepted/correction/next-word/context features; keep v1 readable and
the model fallback exact.

### 6.2 Offline training

- Train the Tier 1 logistic model on the licensed/synthetic corpus from
  Phase 5; CPU is sufficient (16–24 features).
- Produce a checksummed model package with its manifest and training config.
- Evaluate on the frozen holdout; no training on user text.

### 6.3 Tier 2 go/no-go (GPU only if measured)

- A Tier 2 GBDT/MLP is considered only if Tier 1 plateaus.
- GPU (`uiu-h200`) is used only when a licensed holdout shows ≥1.0 pt top-1
  gain and quantised inference stays ≤3 ms p99; otherwise no GPU job runs.

### 6.4 Calibration and canary

- `--ranker v010` cohort behind a settings flag; beta channel first.
- Roll back automatically if top1 or p99 regresses.
- Telemetry is counters only; no text.

### 6.5 Opt-in aggregate contribution

- A separate, explicit Settings action: contribute **counts**, not words.
- Aggregate, k-anonymity threshold, differential privacy, documented retention.
- Never automatic. Custom words stay local unless the user explicitly opts in.
- A global frequency update ships as a signed model/data package, never by
  reading a user's device.

### 6.6 Model acceptance

| Gate | Requirement |
| --- | --- |
| Golden top1 | ≥94.0 % and no top5 regression |
| Licensed holdout top1 | ≥1.0 pt over baseline |
| Ranking p99 | ≤2 ms; Tier 2 ≤3 ms |
| Crash-free sessions | ≥99.5 % in beta |
| Privacy | no text in logs/telemetry; opt-in tests pass |
| Rollback | previous model restores top1 and latency |
