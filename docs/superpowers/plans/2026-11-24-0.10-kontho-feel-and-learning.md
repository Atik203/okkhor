# 0.10.0 — Kontho-feel typing, learning, and model training plan

Status: planned. Owner: Atik. This plan implements the owner's request that
0.10.0 feel like Kontho in daily use and that personal and global learning be
completed in phases.

Evidence base:

- `docs/superpowers/analysis/0.10-suggestions-and-data.md` — WTR1 is fully
  specified; no frequency field exists in either reference; exact Kontho
  trie scoring; our index loses 15.7 % of pairs; baseline golden top1 92.9 %,
  top5 100 %.
- `docs/superpowers/analysis/0.10-kontho-inline-preedit.md` — observed Kontho
  key path, the exact LCP diff, Backspace, Up/Down/Tab, popup timer/ranking,
  reference bugs, and the recommended Okkhor state machine.
- `docs/adr/0021-fixed-layout-engine.md`, `docs/learning.md`,
  `docs/model-roadmap.md`, `AGENTS.md`.

Baseline release for this plan: **0.9.3**.

## Priority rule for 0.10.0

**Beat Kontho in feel and accuracy first; do not optimize size yet.** Artifact,
index and learning-store sizes are recorded for visibility, not used as release
gates. The only hard sizing rules that stay are those needed for safety:
bounded memory, bounded event queues, and no unbounded growth. Compression,
deduplication and aggressive pruning move to 0.11.0/1.0 after the keyboard is
demonstrably better.

## Owner decision (2026-11-24)

- **A now:** global learning is trained from licensed public corpora and
  synthetic data. No user text or custom words leave the device.
- **B later:** the opt-in aggregate contribution is deferred until the keyboard,
  typing feel and suggestions are proven in daily use.
- **Local learning only for now:** personal Smriti learns on-device; the global
  prior is trained offline on the GPU from datasets and shipped as a signed
  package.
- Large-dataset GPU training is in scope for 0.10.0; shipping any model still
  requires a measured A/B win.

## What "beat Kontho" means

| Aspect | Kontho (observed) | Okkhor 0.10 target |
| --- | --- | --- |
| Live per-key Bangla | yes, LCP suffix diff | same feel, grapheme-clamped |
| Backspace | pops one roman char | same, no drift over 200 edits |
| Up/Down live word change | yes | same in Bangla and English |
| Accuracy | ordered pair list, recents-only | full 151k pairs, top1 ≥94 % |
| Layouts | 9 legacy layouts | all 6 working, fixed + phonetic |
| Stability | split erase/inject, codepoint diffs | one atomic batch, anchor check |
| Privacy | sends suggestions to Google | local-only, no network in typing |
| Learning | recents-only (limit 2) | shown/accepted/correction + context |
| Speed | 50 ms popup timer | 30 ms coalescing, p99 budgets |
| Size | small | recorded, **not a gate** |

## Non-negotiable constraints

- Typing never waits on disk, network, UI, AI, or an unbounded lock.
- No raw user text leaves the device without an explicit opt-in action.
- Custom words stay local by default. A global contribution must be opt-in,
  aggregate, differential-privacy protected, and documented.
- No model is enabled by default until a frozen A/B beats the baseline and the
  p99 budget holds.
- `uiu-h200` (H200 1g.18gb) is used only for a measured Tier 2 candidate, never
  for the per-user adapter.

## Phase 1 — Kontho-feel typing (inline preedit)

Goal: the document shows Bangla evolving per keystroke, Backspace walks it back
in the same order, and Up/Down change the word live.

Observed Kontho behaviour to match (evidence in the analysis report):

- text is written **per keystroke, synchronously**; there is no preedit overlay
  and no commit-on-space for the visible text;
- it erases `len(previous_bangla) - LCP(previous, next)` and types **only the
  suffix**;
- Backspace pops one **roman** character and re-renders;
- Up/Down/Tab rewrite the document live through the same diff;
- the popup is coalesced on a **50 ms** timer, capped at **10** rows, and the
  raw roman string is row 0;
- personalisation is recents-only (`RecentsWordsLimit = 2`); there is no
  frequency field and no learned global model.

Okkhor will keep the feel and fix the reference's structural weaknesses:
codepoint-level diffs that split graphemes, separate erase/inject batches, the
one-backspace `completeWordBySpace` assumption, and no anchor verification.

### 1.1 ADR 0022 — inline preedit state machine

- Record: swallow letters in Bangla phonetic mode; keep roman buffer plus the
  last painted preedit; per-key replacement; failure re-emit; Esc revert.
- Define exact state: `roman_buffer`, `last_preedit`, `last_preedit_len`,
  `composition_id`, `frozen_rank_ms`.
- Document undo-history trade-off and the on/off setting.

### 1.2 Inline preedit engine

Use exactly two strings: the roman buffer (source of truth) and `rendered`
(what we last wrote into the document).

- Hook swallows letters in Bangla phonetic mode (same path as fixed layouts).
- On each letter: `next = translate(roman)`; `lcp = common_prefix_utf16(rendered,
  next)`; **clamp `lcp` to a grapheme-cluster boundary** (base + combining marks
  + ZWJ sequences); `erase = rendered.len_utf16 - lcp`; `insert = next[lcp..]`.
- Emit **one atomic `SendInput` batch**: all backspaces, then all Unicode units.
  Never split erase and insert into separate calls (a Kontho bug).
- Skip the call entirely when `erase == 0 && insert.is_empty()`.
- Keep `roman` unchanged while previewing a candidate; typing another letter
  returns to the typed path.
- No preedit until the first dictionary-backed candidate exists; raw Latin is
  not injected.
- Update the popup rows and selection from the same candidate request, keyed by
  a `generation` so stale jobs are dropped.
- On partial `SendInput`, mark the composition dirty and resync from the caret;
  never patch by counting.

### 1.3 Backspace walk-back

- Backspace removes one roman character, recomputes from the prefix cache, and
  replaces the preedit with the shorter form.
- At an empty buffer, the last preedit is erased and the composition ends.
- Focus change, pause, mode switch, layout switch: cancel and leave the last
  preedit in place, never erase another window.

### 1.4 Live Up/Down, Tab, Space, Esc

- Up/Down replace the current document word with the highlighted row through the
  same LCP diff; `roman` stays unchanged so the next letter returns to typing.
  English already previews; extend the identical state machine to Bangla.
- Tab and Space finalize the current preedit; Tab adds no space, Space adds one.
- Esc clears the buffer and **leaves the text** (Kontho behaviour).
- Enter accepts a visible selection only when "Enter accepts" is enabled;
  otherwise it commits and passes through.
- Caret move, click, focus change, pause, layout/encoding change and password
  detection reset the composition; never edit an anchor we no longer own.
- Held keys and overlapping swallowed keys use the per-key swallow flags.

### 1.5 Punctuation and digit choices (Kontho style)

- `.` shows `।` as row 1 and `.` as row 2; default commits `।`, row 2 commits a
  literal dot so `1.2` is typeable.
- Digits show the Bangla numeral as row 1 and the ASCII numeral as row 2;
  default commits Bangla.
- The choice card uses the same non-activating popup and selection keys; it
  never blocks the next character.

### 1.6 Popup feel

- Keep the current in-place card, 30 ms coalescing, sticky width and cached
  widths; Kontho coalesces at 50 ms, so 30 ms is already smoother.
- Hard row cap stays 5–10 (Kontho uses 10).
- Keep the raw Latin row **last**, per ADR 0020, so Space commits Bangla. Kontho
  puts it at row 0; that changes the default commit and is not adopted without
  an explicit owner decision.
- Add per-layout/per-mode QA for no flicker on every key and Backspace.
- Keep placement just below and slightly left of the caret.

### 1.7 Toggle and QA

- Settings: `Inline Bangla preedit` (default on) so a user can fall back to
  commit-on-Space instantly.
- Real-key rows: Notepad, Word, Chrome, VS Code, password field, IME on,
  elevated target, RDP, multi-monitor, undo after commit.
- Automated acceptance tests from the analysis:
  1. golden roman→Bangla edit-plan table for ~200 prefixes (erase, insert);
  2. Backspace property test with no drift over 200 random edits;
  3. grapheme test: `lcp` never splits a base + combining mark;
  4. atomicity test: one `SendInput` call per keystroke;
  5. anchor test: a mutated document refuses the edit and resyncs;
  6. candidate test: row cap, raw-roman ordering, stale generation discarded;
  7. keystroke→edit p99 ≤ 3 ms in the daemon.
- Exit: no lost keystroke, no wrong-window erase, top5 unchanged, p99 within
  budget.

## Phase 3 — Ranking and frequency (B1–B4)

Constraint: no `FeatureVectorV1` change in 0.10.0. Dictionary signals fold into
`base_score`; the shipped logistic model stays valid.

- **B1** deterministic preferred-rank epsilon tie-break.
- **B2** `stage_typo`: transposition at 0.86/0.90, length 3–11, must exist in
  the dictionary, pool capped at 16.
- **B3** bounded preferred-rank weight (−0.015/step, cap −0.06) behind a flag;
  keep exploration slots 3–5 within one score step.
- **B4** optional compound-split strip, never displacing a single word.
- Frequency prior: replace `wordfreq`-only BN popularity with a licensed
  Wikimedia-derived zipf prior (Phase 5 D3), not before it is measured.

Gates: golden top1 ≥94.0 %, top5 =100 %, replay MRR ≥ baseline −0.005,
ranking p99 ≤2 ms, candidate p99 ≤3 ms.

## Phase 4 — Personal learning (C1–C4) and next-word

- **C1** emit `SuggestionShown` / `SuggestionAccepted` with one event per
  `(request_id, position)`, deduped per composition.
- **C2** `Correction` on same-slot retype, plus `NextWordAccepted`.
- **C3** bounded growth, not size optimization: keep a generous safety ceiling
  and measure the real footprint. Do **not** prune aggressively or compact yet;
  retain the data that makes suggestions accurate. Optimization is 0.11.0.
- **C4** privacy tests: no word bytes in logs, password/pause suppression,
  export/delete, no window titles.
- Next-word strip: local bigrams only, confidence threshold, never auto-insert,
  hidden in password fields.

Exit: acceptance rate >0 in a scripted session; taught corrections appear next
time; snapshot stays inside the safety ceiling after a 30-day replay (growth
recorded, not size-optimized).

## Phase 6 — Global model training (phased)

The honest current state: **no global model has been trained on large
datasets.** These phases do that, with gates.

### 6.1 Feature schema v2 + ADR

Add shown/accepted/correction/next-word/context features; keep v1 readable and
the model fallback exact.

### 6.2 Offline training on GPU with large datasets

- Train the global prior and Tier 1/Tier 2 candidates on the licensed and
  synthetic datasets from Phase 5 using `uiu-h200` (H200 1g.18gb, CUDA 13.5,
  project venv, tmux, 200 GB cap, per `AGENTS.md`).
- CPU remains the fallback for small feature sets, but the 0.10 plan explicitly
  includes full-dataset GPU training, not just a toy run.
- Every run records: dataset manifest hashes, split hashes, hyperparameters,
  seed, git commit, and evaluation output.
- Produce a checksummed model package with its manifest and training config.
- Evaluate on the frozen holdout; no training on user text.

### 6.3 Tier 2 decision

- A Tier 2 GBDT/MLP is trained on the GPU alongside Tier 1 when the dataset is
  large enough.
- Ship it only if a licensed holdout shows ≥1.0 pt top-1 gain and quantised
  inference stays ≤3 ms p99; otherwise ship the better Tier 1 model.

### 6.4 Calibration and canary

- `--ranker v010` cohort behind a settings flag; beta channel first.
- Roll back automatically if top1 or p99 regresses.
- Telemetry is counters only; no text.

### 6.5 Opt-in aggregate contribution (deferred)

- Decision: **B is later.** This section is the design record, not a 0.10.0
  deliverable.
- When it returns: a separate, explicit Settings action that contributes
  **counts**, not words; aggregate, k-anonymity, differential privacy,
  documented retention; never automatic; custom words stay local.
- A global frequency update ships as a signed model/data package, never by
  reading a user's device.

### 6.6 Model acceptance

| Gate | Requirement |
| --- | --- |
| Golden top1 | ≥94.0 % and no top5 regression |
| Licensed holdout top1 | ≥1.0 pt over baseline |
| Ranking p99 | ≤2 ms; Tier 2 ≤3 ms |
| Crash-free sessions | ≥99.5 % in beta |
| Privacy | no text in logs/telemetry; opt-in tests pass |
| Rollback | previous model restores top1 and latency |
