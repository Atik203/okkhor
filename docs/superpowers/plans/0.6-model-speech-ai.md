# 0.6 — Tier 1 reranker, speech, and AI worker

Plan of record for milestone 0.6. Binding rules: `AGENTS.md`, ADR 0002
(AI off the hot path), ADR 0007 (hybrid learning-to-rank),
`docs/model-roadmap.md`, `docs/security-privacy.md`.

## Global constraints

- Typing is sacred. No model, speech, or AI call is reachable from the hook or
  input worker. A miss or outage returns the deterministic Smriti/engine result.
- No raw user text leaves the device. Training uses licensed public corpora or
  synthetic data generated from our own layouts and dictionaries.
- Every learned model has a hard inference deadline, a baseline fallback, and a
  versioned feature schema. No ONNX, transformer, or GPU runtime in 0.6.
- Speech and AI are opt-in, cancellable, cached, and never log text or audio.
- The worker is a separate process. A worker crash must not stop typing.
- No API keys committed. Providers are behind traits; tests use mocks.
- No cloud calls in CI. Network adapters are feature-gated and tested with a
  local fake server.

## Merge order

`1 → 2 → 3 → 4 → 5`. Task 2 depends on Task 1's replay set and feature
extraction. Tasks 3 and 4 are independent of 1–2 and may run in parallel once
0.5 is merged; the lead resolves `Cargo.toml` conflicts.

## Task 1 — Feature schema v1, replay harness, synthetic dataset

Deliver:

1. `crates/okkhor-learn` (additive):
   - `FeatureVectorV1` matching `docs/model-roadmap.md` §"Feature schema v1":
     `base_score`, `candidate_source`, `language`, `layout`, `prefix_len`,
     `word_len`, `user_word_count`, `pair_count`, `recency`,
     `acceptance_rate`, `correction_rate`, `bigram_score`, `phonetic_score`,
     `is_user_vocab`, `context_language`, `script_mix`. Stable order and
     explicit `SCHEMA_VERSION = 1`.
   - `extract_features(&SuggestionRequest, &Candidate, &SmritiSnapshot) -> Result<FeatureVectorV1, FeatureError>`
     with no I/O and no allocation beyond a bounded vector.
   - Determinism test: same inputs → byte-identical vector.
2. `apps/okkhor-bench` or a new `tools/okkhor-replay` (pick the smaller diff;
   prefer `crates/okkhor-train` with a `replay` binary):
   - Replay format v1 (JSONL, one case per line):
     `{schema, case_id, language, layout, prefix, context, expected:[...], shown:[...], accepted:null|index, candidates:[...]}`.
   - Frozen synthetic replay set under `crates/okkhor-train/data/synthetic-replay.jsonl`,
     generated from the committed synthetic corpus and layout fixtures; at
     least 200 cases, committed, reproducible by a generator command.
   - Evaluation metrics: top-1, top-5, MRR, acceptance rate, keystroke savings,
     and per-language/per-layout segments; p50/p95/p99 ranking latency.
   - Output `--json` and a markdown report; write under git-ignored
     `bench-out/`.
3. Baseline report: run Smriti and the engine on the replay set; record numbers
   in `docs/performance.md` as a labeled row (commit, date, profile, OS,
   synthetic-only caveat).
4. Docs: `docs/model-roadmap.md` gains the exact replay schema and the
   synthetic-data provenance; `docs/learning.md` gains the feature contract.

Acceptance:

- `cargo test -p okkhor-learn -p okkhor-train` green; root checks green.
- Generator is deterministic (same seed → same file, checksum recorded).
- No user data, no legacy execution, no network.

## Task 2 — Tier 1 logistic reranker (train + runtime + A/B)

Deliver:

1. `crates/okkhor-train` (offline, not shipped in the app):
   - Deterministic logistic regression trainer (plain Rust, no Python, no GPU):
     L2 regularization, fixed iteration count, seeded shuffle, feature
     standardization saved in the model.
   - `train --replay <path> --out <model.json>`; train/validation split by
     `case_id` hash; refuse to train on < 200 cases.
   - Model JSON: `schema`, `name`, `version`, `feature_schema: "v1"`,
     `weights`, `bias`, `means`, `scales`, `trained_at`, `dataset_sha256`,
     `metrics {top1, top5, mrr, p99_ms}`, `notes`.
2. `crates/okkhor-model` (shipped, `#![forbid(unsafe_code)]`):
   - Parse/validate the model JSON (finite weights, matching feature schema,
     bounded weight magnitude), checksum the file, and expose
     `LogisticReranker::score(&FeatureVectorV1) -> f32` with a deadline.
   - `HybridRanker` implementing `Ranker`: compute baseline order, rescore
     within a deadline (`< 1 ms`), fall back to baseline on any error/expiry;
     blend `final = baseline + confidence * model_delta` where `confidence`
     grows with local evidence (contract in `docs/learning.md`).
   - Load only a bundled model by default. Reject unsigned downloaded models
     unless a public key is configured; checksum is mandatory in all cases.
3. Integration: `okkhor-engine`/daemon rank path uses `HybridRanker` behind
   `--ranker hybrid|baseline` (default `baseline` until the A/B report is
   accepted). No new allocation per keystroke; preallocated feature buffer.
4. A/B report: baseline vs hybrid on the frozen replay set, with top-1/top-5
   deltas, p99, and a clear statement that the dataset is synthetic. If hybrid
   does not beat baseline, ship it disabled and record the negative result
   rather than tuning on the test set.
5. Tests: model parse/validation failures, checksum mismatch, deadline expiry
   fallback, determinism, no-panic on NaN/Inf, feature-order mismatch
   rejection, and a golden score vector.

Acceptance:

- Hybrid p99 < 1 ms on the reference replay run; fallback proven by a test.
- Root checks green; `okkhor-train` excluded from release artifacts.
- No quality claim beyond the synthetic replay report.

## Task 3 — `okkhor-ai` worker, broker, and UI panel

Deliver:

1. `crates/okkhor-ai` (`#![forbid(unsafe_code)]`):
   - `AiProvider` trait (async or blocking worker thread), `AiRequest`
     (prompt, system, max_tokens, temperature, timeout), `AiResponse`
     (text, model, usage, latency), typed `AiError`.
   - `MockProvider` (deterministic, tests), `DisabledProvider`.
   - `AiCache`: bounded LRU (default 64 entries, 256 KiB total), key =
     SHA-256(system + prompt + model + prompt_version), in-memory only in
     0.6; no text on disk.
   - `CircuitBreaker` (closed/open/half-open, failure threshold, cooldown),
     single-flight per key, debounce helper, cancellation token.
   - `Policy`: requires explicit opt-in, rejects calls on the typing path,
     enforces 250 ms idle, max 1 in-flight, 15 s timeout, no logging of text.
   - Optional `GeminiProvider` behind feature `http` using `reqwest`
     (`rustls-tls`, `json`), reading the key from the environment variable
     `OKKHOR_GEMINI_API_KEY`; never persisted or logged. Tests use a local
     fake HTTP server only.
2. `apps/okkhor-worker`: separate process, no window, bounded job queue (16),
   cancellation, health ping, and an IPC server on its own pipe/token passed by
   the daemon. The daemon proxies `ai.complete` after policy checks; the UI
   never talks to the worker directly.
3. Daemon: spawn/reap the worker, forward jobs, return typed errors, expose
   `ai.status` (enabled, provider, circuit state) without text.
4. UI: Settings → AI section with opt-in toggle, provider select, key presence
   indicator (set/unset only), and a "Try a rewrite" panel that requires an
   explicit click, shows a spinner, supports Cancel, and displays the typed
   error. No keystroke or selection capture in 0.6; the panel uses text the
   user pastes explicitly.
5. Docs: `docs/ai.md` with privacy, data flow, provider config, failure modes;
   `docs/security-privacy.md` updated (no disk cache in 0.6).

Acceptance:

- No AI code linked into the daemon hot path; adding the worker does not change
  hook/ranking benchmarks beyond noise.
- Tests: cache eviction, key stability, breaker transitions, single-flight,
  cancellation, timeout, policy rejection, disabled provider, fake-server
  success/error mapping. No real network.
- Worker kill test: daemon keeps typing; next AI call returns `WorkerDown`.

## Task 4 — `okkhor-speech` capture and transcription worker

Deliver:

1. `crates/okkhor-speech` (`#![forbid(unsafe_code)]`):
   - `AudioSource` trait, `AudioChunk` (PCM16 mono 16 kHz), bounded ring
     buffer (max 30 s), `WavFileSource` (PCM16 only, validated header), and
     `MicSource` behind feature `mic` using `cpal` (default input device,
     resample to 16 kHz with a small linear resampler).
   - `SpeechProvider` trait, `MockProvider`, `DisabledProvider`, and optional
     `GoogleSpeechProvider` behind `http` (env `OKKHOR_GOOGLE_SPEECH_KEY`),
     fake-server tested.
   - Segmentation: simple energy gate + max segment 10 s; no ML VAD in 0.6.
   - Privacy: audio is transient, never written to disk except an explicit
     user-chosen export; transcripts are not logged.
2. Worker integration: `speech.transcribe` job with start/stop/cancel; the
   daemon proxies after opt-in; 30 s hard cap; no overlap.
3. UI: Settings → Speech section (opt-in, provider, mic device list via
   worker, key presence) and a Dictation panel that records only while the
   button is held/clicked, shows elapsed time, Cancel, and inserts the
   transcript into a text area (user copies or explicitly inserts; no
   automatic typing). System-loopback capture is **not** in 0.6 and is
   documented as a gap.
4. Docs: `docs/speech.md`; privacy notes; permissions (microphone) guidance.

Acceptance:

- Tests: WAV parse/reject, ring-buffer bounds, segmenter, cancel, timeout,
  provider error mapping, fake-server path. No microphone in CI.
- No audio or transcript in logs; worker death does not affect typing.
