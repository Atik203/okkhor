# 0.6 — Suggestion quality, English completions, instant state

Plan of record for milestone 0.6. This plan supersedes the 0.6
model/AI scope in `0.6-model-data-ai.md`; datasets, the Tier 1 reranker and
the AI worker move to 0.7/0.8. Binding rules: `AGENTS.md`, ADR-0016,
ADR-0002 (AI off the hot path), ADR-0003 (Smriti), ADR-0014 (input modes).

## Goal

Typing feels finished:

- the correct Bangla word is in the top three for everyday input;
- eight useful rows are visible by default, up to ten;
- English mode offers quiet prefix completions that never auto-replace;
- the quick-bar chip changes the moment F9/tray/pause changes the engine;
- Settings is easy to use at every window size in light and dark.

## Global constraints

- The hook and input worker never wait on UI, disk, network, AI, or an
  unbounded lock. Suggestion data is loaded once at startup.
- No new crate, process, protocol, or database without an ADR.
- The suggestion index is a committed, deterministic binary generated from
  owner-provided dictionaries; no source path is committed.
- Corrupt or missing index data fails closed to the rule-only path and never
  panics.
- `okkhor-core`, `okkhor-engine`, `okkhor-learn` stay `#![forbid(unsafe_code)]`.
- English completions never replace text on Space/Enter/punctuation. Only an
  explicit Tab/click accepts.
- Do not parse legacy `WTR1` binary tries in 0.6. The Avro SQLite database,
  `autodict.dct`, the curated starter list, and `wordfreq` are the sources.
- Every hot-path change carries before/after measurements.
- One PR, one worktree, one release tag; only the lead merges/publishes.

## Data source findings (2026-11-24)

- `avro_portable/Database.db3`: 159,426 unique Bangla words in 47 onset
  tables, plus a 749-row `Suffix` table; no frequency column.
- `avro_portable/autodict.dct`: 2,481 lines of roman→roman autocorrect pairs.
- `Nms Kontho .../bangla_dict.bin`: WTR1 binary trie, 135,410 roman→Bangla
  pairs. A validated leaf scanner imports 114,193 clean lowercase pairs; the
  trie is not reconstructed. This covers the rule table's inherent-vowel
  gaps (`ghor`, `mangsho`, `jabo`, `koro`, `korechi`).
- `wordfreq` supplies zipf popularity for Bangla and English, and its top
  Bengali list fills common forms missing from the Avro database.

## Tasks

### Task 1 — Data build + index + manifest

Deliver:

1. `scripts/build-suggestion-index.py`:
   - reads `--avro-home` (defaults to `E:\Nms_Kontho\avro_portable`) and
     `--starter` (defaults to the daemon starter JSON);
   - reads all Avro word tables, the `Suffix` table, and `autodict.dct`;
   - imports the Nms `WTR1` leaf records with a validated scanner and a
     known-mapping gate;
   - adds `wordfreq.top_n_list('bn', 50000)` and `top_n_list('en', 60000)`,
     filtered to letters/apostrophe, NFC-normalized, deduplicated;
   - emits `crates/okkhor-engine/assets/suggest/suggest-v1.bin` and
     `manifest.json` with source SHA256s, counts, `wordfreq` version, and the
     index SHA256. No absolute paths, no timestamp.
2. `scripts/requirements-suggest.txt` pinning `wordfreq`.
3. `scripts/verify-suggestion-index.ps1` checks the manifest hash.
4. `docs/design/suggestion-data.md` documents the pipeline and counts.

Index format `OKS1`:

```
magic u32 "OKS1"
version u16, section_count u16, reserved u32
section table: id u32, offset u32, len u32, count u32
sections: POOL, CURATED, BN, BN_POP, AUTOC, SUFFIX, EN, EN_POP, META, ROMAN
CURATED: (roman_off u32, roman_len u16, out_off u32, out_len u16)
BN/EN: (text_off u32, text_len u16, zipf u16) sorted by UTF-8 bytes
BN_POP/EN_POP: u32 indices sorted by zipf desc, then text
AUTOC/SUFFIX/ROMAN: (key_off u32, key_len u16, val_off u32, val_len u16)
META: JSON bytes
```

Acceptance:

- ≥150k Bangla words before wordfreq union, ≥2k autocorrect pairs,
  ≥50k English words, ≥100k roman pairs.
- Two runs produce byte-identical output (same SHA256).
- Index ≤11 MiB; every string valid UTF-8; sections bounds-checked.
- `manifest.json` records counts and source hashes; no source path leaks.

### Task 2 — Engine lookup + ranking + golden corpus + bench

Deliver:

1. `crates/okkhor-engine/src/suggest/` with `SuggestionIndex`,
   `SuggestionEngine`, `SuggestionConfig`, `SuggestionError`.
2. Stage order (documented in ADR-0016):
   curated exact → user exact → roman exact/prefix → autocorrect exact → rule
   output exact/vowel variant → dictionary exact → dictionary prefix → suffix
   expansion → merge/dedup → `Smriti::rank` → top N.
3. Query rules: max 64 staged candidates, max 8 rule outputs, popularity scan
   capped at 40 matches, deterministic ordering, no I/O/clock/unsafe.
4. `tests/fixtures/suggestions/golden-v1.json`: ~150 hand-checked
   roman→expected cases, including common words, prefixes, `korcho`, `bhalo`,
   `dhonnobad`, `valobasha`, digits, and known gaps.
5. `apps/okkhor-bench --suggestions`: top-1/top-5/MRR and p50/p95/p99.

Acceptance:

- measured 2026-11-24 on the development machine: top-1 105/113 (92.9%),
  top-5 113/113 (100%), suggestion p50 0.37 ms / p95 0.68 ms / p99 0.80 ms
  over 2,000 prefix queries (release build); keep the 80/95 gates and the
  3 ms p99 budget;
- corrupt magic/version/offset/UTF-8 fails closed; no panic;
- `cargo test -p okkhor-engine` and clippy green.

## Risks

- Ranking still misses variant spellings → golden corpus first; explicit-vowel
  and suffix variants; WTR1 roman index deferred.
- English Tab feels intrusive → exact-match hide, Esc, Settings toggle.
- Caret thread regression → go/no-go measurement.
- Smriti lock contention → short sections; measure p99.
- Index size → ~10.2 MiB embedded; split to a data file if needed.
