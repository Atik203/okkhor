# SDD plan: 0.4 candidate engine

## Goal

Turn the 0.3 skeleton crates into a working local suggestion pipeline:
dictionary prefix lookup + transliteration application + Smriti ranking,
measured against a synthetic golden corpus.

This is the first slice of roadmap phase 2 (0.3 Bornomala core) exit
criteria that the skeleton sprint could not reach: top-5 parity on an
approved corpus and local candidate p99 <3ms.

## Global constraints

Same as the 0.3 sprint, plus:
- New crate `okkhor-engine` requires ADR-0011 before code (AGENTS.md rule).
- Golden corpus is synthetic-only, committed under
  `crates/okkhor-engine/tests/fixtures/synthetic/`.
- No changes to `okkhor-core` public types without an ADR.
- Real legacy asset importers stay deferred (proprietary formats, no
  redistribution rights confirmed); synthetic fixtures remain the corpus.
- Benchmarks: release build, p50/p95/p99/max + correctness, same protocol as
  `docs/performance.md`. Hook-level keydown measurement stays in issue #8.
- Every agent uses `opencode-go/muse-spark-1.3-contributor`.
- No agent pushes, merges, creates PRs, or edits GitHub issues. Lead integrates.

## Tasks

### Task 1 - ADR-0011 + golden corpus schema (docs, blocking)

Write `docs/adr/0011-candidate-engine.md` and
`docs/design/0.4-engine-contracts.md`: the `okkhor-engine` public API
(`CandidateEngine::suggest(request) -> Vec<Suggestion>`), composition of
`okkhor-lang` + `okkhor-transliterate` + `okkhor-learn::Smriti`, per-language
budgets, golden corpus schema (input prefix, language, layout, expected top-5,
context), and the parity metric definition (top-1/top-5 hit rate). No code.

### Task 2 - Implement `okkhor-engine` (code)

New crate per ADR-0011: normalized prefix lookup over `Dictionary`,
transliteration rule application for Romanized input, merge + dedup,
`Smriti::rank` top-N truncation. Deterministic ordering, bounded allocation,
no I/O on the query path. Unit tests + golden-corpus test (synthetic,
committed). One workspace-member line for this crate only.

### Task 3 - Benchmark + parity report (bench + docs)

Extend `okkhor-bench` with a `--candidates` mode running the golden corpus:
report top-1/top-5 hit rate and rank latency p50/p95/p99/max. Update
`docs/performance.md` with the measured table only. No reference-machine
claims on a shared desktop.

### Task 4 - Review + merge (lead)

Per-task reviews with fix loops (max 5 rounds), then merge in order
ADR -> engine -> bench, verifying main CI each time. Close the loop with a
scoped re-review per fix wave. Update issues, delete worktrees, tag nothing
(0.4 ships as part of the 0.3 milestone line; version bump only at release).

## Merge order

1. ADR-0011 + contracts (docs)
2. `okkhor-engine` (code, reviewed)
3. bench + performance docs (reviewed)

## Open questions for the owner — resolved 2026-11-23

- Real legacy dictionary/layout formats: APPROVED for reuse with adaptation.
  Read-only finding: `*.bin` dictionaries use a custom `WTR1` magic +
  version (e.g. `1.2`) binary trie matching `word_trie.dll`; `.nmsLayout` /
  `.nmsEnco` files are serialized dicts with metadata (`name`, `type`,
  `lang`, `dic`, `reverseMap`, `version`, `modification-time`,
  `developerName`), a `keyMap`, `compiledKeys`, and regex rules. Importers
  must be validated with tests; never commit proprietary bytes.
- Differential testing: APPROVED in a disposable VM with synthetic fixtures
  only, never on the daily driver. Parity claims stay synthetic-only until a
  VM run is recorded.
