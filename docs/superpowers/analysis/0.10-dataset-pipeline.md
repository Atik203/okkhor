Status: tooling and policy are in place. No corpus was downloaded and no GPU job
was run for this change. The first real run is the operator step that turns
licensed corpora into a frozen train/eval collection.

## 1. Scope and invariants

The pipeline prepares the global prior and training/evaluation data for 0.10.
It does not ship a model, change the default ranker, or touch the typing path.

Invariants:

- no network access in the tool;
- no user text, learning store, logs, clipboard, or telemetry input;
- licensed or synthetic corpora only, explicit licence and provenance;
- fail closed on a missing licence, missing attribution, non-commercial training
  data, or train/eval contamination;
- evaluation is frozen before tuning and is never used for the frequency prior;
- committed repository content is manifests, checksums, and tiny synthetic
  fixtures only.

Only these five sources feed the 0.10 collection. Exact identifiers, licences,

## 3. Local preparation

### 3.1 Corpus directory

```text
<corpus-root>/<collection>/
  dataset-sources.json
  banglatlit.tsv
  dakshina-bn.tsv
  wikimedia-bn.txt
  banglasec-train.tsv
  banglasec-nc-eval.tsv
  synthetic-pairs.tsv
  synthetic-holdout.txt
```

The real filenames depend on the download; record them in
`dataset-sources.json`. Vendor formats are converted once by the operator to
these row shapes; record the converter and the resulting row counts in the run
notes. The Wikimedia dump is XML: extract plain text on the remote machine
first, then feed the extracted text file to the pipeline. The pipeline never
parses the raw dump and never downloads anything.

Rows are `pairs`/`corrections` (`input`/`roman` +
`target`/`bangla`) or `sentences` (`text`), in TSV/CSV with a header, JSONL, or
one-sentence-per-line TXT. `case_id` and `language` are optional.

`dataset-sources.json` follows the example in `docs/design/datasets.md`. Required
per file: `path`, `name`, `kind`, `role`, `license`, `source`, `languages`, and
`attribution` when the licence requires it. The `frequency` block is required
because Bangla tokens are present; use the Wikimedia licence and attribution.

### 3.2 Validate before writing

From the repository root:

```powershell
python -m py_compile scripts/prepare-datasets.py

python scripts/prepare-datasets.py `
  --input <corpus-root>\<collection> `
  --out <prepared-root>\<collection> --dry-run
```

Expect `"ok": true`, `train_rows` and `eval_rows` counts, input hashes, the
licence table, and the frequency bucket summary. Nothing is written. A non-zero
exit prints every licence/provenance problem at once.

### 3.3 Build and verify

```powershell
python scripts/prepare-datasets.py `
  --input <corpus-root>\<collection> `
  --out <prepared-root>\<collection>

python scripts/prepare-datasets.py --out <prepared-root>\<collection> --verify

Get-ChildItem -Recurse <prepared-root>\<collection> -Filter *.manifest.json |
  ForEach-Object {
    cargo run -q -p okkhor-train --bin okkhor-train-dataset -- --verify $_.FullName
  }
```

Expected tree:

```text
<prepared-root>/<collection>/
  collection.json
  train/<source>.jsonl + <source>.manifest.json
  eval/<source>.jsonl + <source>.manifest.json
  freq/bn-tokens.tsv + bn-tokens.manifest.json
```

`collection.json` records: tool version, split rule and threshold, source
manifest hash, every input path/hash/size/row count, duplicate/blank/PII drop
counts, every output data and manifest hash, row totals, Bangla token totals,
zipf buckets, licence summary, and required attributions.

Fixture expectations, used as the CI reference:

```text
name:      fixture-synthetic
train:     16 rows
eval:      3 rows (1 hashed pair row + 2 forced holdout sentences)
tokens:    31 total, 27 distinct, all zipf bucket 4
manifests: 5, all accepted by okkhor-train-dataset --verify
```

### 3.4 Determinism check

Build twice into separate directories and compare file hashes:

```powershell
python scripts/prepare-datasets.py --input <corpus-root>\<collection> --out $env:TEMP\ds-a
python scripts/prepare-datasets.py --input <corpus-root>\<collection> --out $env:TEMP\ds-b
# compare relative paths + SHA-256; expect identical trees
```

The tool has no timestamps, random ids, hostnames, or absolute paths in output.
Same input bytes + same tool version + same arguments must produce the same
`collection.json` hash. If a rebuild differs, stop and inspect before uploading.

### 3.5 What to inspect before upload

- `eval_rows` is at least 1,000 for the ship-gate holdout, and every eval row is
  from a licensed or synthetic source;
- `dropped_pii` and `duplicates` are plausible and nonzero drops are understood;
- `bangla_tokens` is large enough for the frequency prior; the D3 target is
  ≥120,000 distinct Bangla words in the index/prior, which is measured at
  evaluation, not assumed from this run;
- the licence table shows no unexpected licence and no non-commercial file in a
  `train` role;
- attributions are copied into `THIRD_PARTY_LICENSES.md` and the About screen in
  the artifact change. This repository change does not edit those files.

## 5. GPU stage (`uiu-h200`)

Training is allowed only for a Tier 2 candidate under the go/no-go rule in §6.
Tier 1 remains CPU-sized; if the candidate does not clear the gate, no GPU job is
needed.

### 5.1 Rules

- SSH alias `uiu-h200` only; no extra ports or connection methods.
- MIG slice `1g.18gb`, 18 GB VRAM maximum; never request a larger profile.
- Driver `580.178.04`, CUDA `13.5`; do not change, reinstall, or replace system
  libraries.
- Project-local virtual environment only; no `sudo`, no system packages, no
  system changes outside the project space.
- Long jobs under `tmux`/`screen`; stop idle jobs.
- Project space ≤200 GB; run `df -h` and `du -sh` before writes.
- Never commit or log a hostname, username, account id, token, key, or
  fingerprint. The only allowed identifiers are `uiu-h200`, `H200 1g.18gb`,
  driver `580.178.04`, and `CUDA 13.5`.
- No user text, no raw keystrokes, no unrelated workload.

### 5.2 Inputs transferred

Transfer only prepared artifacts, not raw downloads:

```text
<project-root>/okkhor/data/prepared/<collection>/
  collection.json
  train/**
  eval/**
  freq/bn-tokens.tsv
  **/*.manifest.json
<project-root>/okkhor/configs/<run>.json
```

Before transfer, record the local `collection.json` SHA-256. After transfer,
re-run `--verify` on the remote copy; a hash mismatch aborts the run.

### 5.3 Environment and job

```bash
cd <project-root>/okkhor
df -h . ; du -sh data
python3 -m venv venv            # only if not present
. venv/bin/activate
python -m pip install -U <pinned training deps>   # project venv only
tmux new -s okkhor-v010
# inside tmux: run the trainer with the config and seed
python train/reranker.py --config configs/v010.json --seed <seed> --out runs/<run-id>
```

No token is written to a file or the repository. The HF token, if needed at all,
is passed in the command environment and never echoed.

### 5.4 Outputs

```text
<project-root>/okkhor/runs/<run-id>/
  model.onnx | coefficients.json
  model.manifest.json
  training-config.json
  metrics.json
  eval.log            # counters only, never corpus text
```

The package manifest records dataset collection/manifest/data hashes, the frozen
split hash, seed, hyperparameters, git commit, environment, and metrics. The exact
shape is in `docs/model-roadmap.md` §"Package manifest". Copy the package,
`metrics.json`, and manifest into the repository only as the small committed
artifact the release process expects; do not copy the prepared corpora or raw
downloads.

## 6. Go/no-go

Ship a model only if the frozen licensed holdout beats the 0.9.3 baseline by
**≥1.0 percentage point top-1** and quantised inference stays **≤3 ms p99**.
All of the following must hold:

| Gate | Requirement |
| --- | --- |
| Licensed holdout top-1 | ≥ baseline + 1.0 pt |
| Licensed holdout top-5 | no regression |
| Golden top-1 | ≥94.0 % |
| Golden top-5 | 100 % |
| Tier 1 ranking p99 | ≤2 ms |
| Tier 2 quantised p99 | ≤3 ms |
| Rollback | restores previous top-1 and latency |
| Privacy | no text in logs/telemetry; opt-in tests pass |

If any gate fails, ship the baseline and record the negative result. Synthetic
or fixture gains do not count. A positive holdout result still goes behind the
`v010` cohort flag, beta channel first, with automatic rollback on a top-1 or
p99 regression.

## 7. Fail-closed behaviour

| Condition | Result |
| --- | --- |
| missing/blank `license` | exit 1, no output |
| unknown licence id | exit 1, no output |
| missing attribution for MIT/CC-BY/CC-BY-SA | exit 1, no output |
| non-commercial file with `role: train`/`hash` | exit 1, no output |
| absolute or `..` path in the source manifest | exit 1, no output |
| same `case_id` in two source files | exit 1 (contamination) |
| `case_id` in both train and eval | `--verify` fails |
| data file changed after build | `--verify` fails on hash |
| frequency TSV inconsistent with train rows | `--verify` fails |
| output directory non-empty without `--force` | exit 1, no overwrite |
| input and output directories overlap | exit 1, no output |
