## 1. The key path, start to finish

### 1.1 What intercepts a key [OBS]

Two cooperating layers:

1. `pynput.keyboard.Listener(on_press=self.on_press, on_release=self.on_release)` —
   created in `Ui.__init__` and re-created inside `write_text` (L7659); it is the
   observer that feeds `on_press` (L6834).
2. The boppreh `keyboard` module (`kb2`) — `block_key()` / `unblock_key()`
   perform the *suppression* (`blockKey` L124, `unblockKey` L137,
   `Ui.blockKeys` L6676). Blocked keys never reach the target application, but
   the pynput listener still sees them.

`Ui.blockKeys(state)` (L6676) blocks, per language:

- every identifier in `self.currentKeysToblock` (loaded from the layout's
  `keysToBlock` list),
- every identifier in `keysToBlockForEncoder` / `…_english`,
- the numeric-pad cluster `(72,80,71,73,75,76,77,79,81,82)` when
  `BanglaNumPad` is on.

Consequence **[INF, consistent with all code paths]**: in Bangla mode the raw
ASCII/roman letter never lands in the document; only Kontho's own
`keyboard.write(...)` output does. That is why the document shows transliterated
text at all.

A second, separate mechanism exists for edge cases: `overLapedKeys` +
`blockKey`/`unblockKey` around `kb.tap(key)` in `on_press` (L686–914) re-emits a
key that must be both blocked (for the OS) and delivered (for the app).

Two `globalKeys.exe` processes (AutoHotkey hosts) are children of the Kontho
process and exist for *hotkeys*, not for character suppression — see §8.

### 2.1 The exact erase/inject pair [OBS]

`Ui.smertCompletor(word_soFar, the_word, case_sensetive=False)` — L6551:

```python
if not case_sensetive: word_soFar = word_soFar.lower()
index = 0
while (index < len(word_soFar) and index < len(the_word)
       and word_soFar[index] == the_word[index]):
    index += 1
if index == len(word_soFar) and index == len(the_word):
    return (0, '')
return (len(word_soFar) - index, the_word[index:])
```

Therefore, for the overwhelmingly common "cursor at end of word" case:

- **Erase length** = `len(previous_rendered_bangla) - LCP(previous, new)`
  backspaces, issued **one `Key.backspace` tap each**.
- **Inject** = `new[LCP:]` — the *suffix only*, written through
  `keyboard.write()` (Unicode `SendInput` per character).
- If the translation is unchanged the pair is **`(0, '')` → nothing is sent**.

Worked example (rule-engine output, not literal Kontho data):

| step | roman buffer | rendered now | rendered next | backspaces | typed |
| --- | --- | --- | --- | --- | --- |
| 1 | `a` | — | `অ` | 0 | `অ` |
| 2 | `am` | `অ` | `আম` | 0 | `ম` |
| 3 | `ama` | `আম` | `আমা` | 0 | `া` |
| 4 | `amar` | `আমা` | `আমার` | 0 | `র` |
| 5 | `amr` | `আমার` | `আমর` | 1 (`র`) | — |

Note that steps 1–4 write *incrementally*: because the previous render is a
prefix of the next, backspaces are 0 and only the delta is typed. Step 5 shows the
retro-edit case.

**This is a codepoint-level diff, not a grapheme-level diff.** If the LCP falls
between a base consonant and its vowel sign or virama (e.g. re-deriving a
conjunct), the backspace count can land *inside* a cluster. Windows text services
process backspace as one UTF-16 code unit, so the intermediate state can be a
dangling combining mark; it is repaired by the immediately following
`keyboard.write()` because the erase and the injection are back-to-back. **[OBS
for the algorithm; INF for the intermediate-rendering hazard]** — the latter was
not visually verified (see §7).

different input APIs, and **the pynput listener is stopped for injection but not
for the backspace loop**.

So **one Backspace removes exactly one character from the roman buffer**, then the
word is re-translated and the document is re-rendered by diff. Consequently the
Bangla text can shrink by 0, 1, or several codepoints for a single Backspace (0
when two different roman tails map to the same Bangla, e.g. deleting a redundant
`h`), and a single Backspace may leave the document unchanged while the popup
updates.

`restore_word_at_current_cursor_position('Key.backspace', props)` (L7697) handles
the "empty buffer + previous word" case: it restores the raw properties and the
previously committed word, so Backspace at the start of a word steps back into
the *previous* word rather than deleting its last character. This is the
`wordByWordBackup` setting.

`blockBackSpace(True)` + `wordBeingSelectedFromScratch` implement the "undo the
suggestion, not the character" rule: the first Backspace after accepting a
candidate re-renders the **first** candidate row instead of shortening the word
(`on_press` L6342–6724: `setCurrentRow(0)`, trim `CustomLayoutkeyHis`,
`blockBackSpace(False)`, `tempoComplition(item.text, True)`).

## 4. Does the text appear per keystroke or on space? [OBS]

**Per keystroke, synchronously, on the listener thread.** `on_press`'s default
branch calls `convertToLayout(...)` inline; `convertToLayout` ends with the
backspace loop + `write_text(rest_wrd)` before returning. Space adds *one extra*
`convertToLayout(' ')` for space-sensitive rule tables (`spacePatternPresent`,
`translator.py:__init__` prints `"space patter present …"` when the compiled table
contains a space pattern). There is no "commit on space" gate for ordinary words
and no preedit overlay widget: the document always holds the current best render.

The only asynchronous part is the **suggestion popup**, driven by
`word_debounce_signal` (see §7).

Documented side effects of that choice **[INF, standard consequence]**:
each keystroke is a real edit → one undo step per keystroke, and any host
autocorrect/autocompletion competes with Kontho's own rewriting.

## 5. Conjuncts / vowel signs / whole-word re-render [OBS + INF]

- The whole roman buffer is re-translated on every key: `layout_tr.translate(englishWordSofar)`
  always receives the **full** word, never an incremental fragment. There is no
  partial/streaming state machine inside the Python layer; conjunct formation is
  entirely a property of the native rule table.
- Because the render is diffed against the previous render, a conjunct that forms
  late (e.g. `k` `sh` `m` → `ক্ষ্ম`) causes the LCP to fall early, so several
  backspaces fire and a longer suffix is typed.
- `myIgnoreCharacters` and `myNonJoinerCharacters` are layout-driven override
  lists: ignore-chars are stripped from both sides before diffing (so ZWNJ/ZWJ
  and encoder padding never influence the diff), non-joiners get their own
  insertion branch (§2.2 branch C).

## 6. Up / Down / Tab / Enter / Esc [OBS]

`_NAV_KEYS` branch (L3260–5578). Preconditions: popup `centralwidget.isVisible()`
and the corresponding setting (`using_arrow`, `using_tab`).

| Key | Behaviour |
| --- | --- |
| **Down** | `selectNextWord()` → normally `setCurrentRow(row+1)`; **at the last row it does not simply wrap**: if `wordSofar in ('', ' ')` it goes to row 0, otherwise it jumps back to row 1 (or row 2 when `currentRow == -1`, Bangla and `selection_checked2`), i.e. it cycles candidates without landing on the raw-roman row. Then, if `selection_checked2`, `tempoComplition(currentItem.text)` — **the document text is replaced immediately** (live preview) |
| **Tab** | if `using_tab`: Shift not pressed → `selectNextWord()`, else `selectPreviousWord()`; then, if `selection_checked2`, `tempoComplition(...)`. Tab is blocked at the OS level (`blockKey(15)`) while the popup is visible, so focus does not move |
| **Up** | if `currentRow != -1`: `selectPreviousWord()` (+ `tempoComplition` when `selection_checked2`); if `currentRow == -1`: `initSentence()` (clear) |
| **Enter** | if a row is selected and `selection_checked1`: commit that row — `WordClicked(i_text)`, `wordSofar = i_text`, `convert_to_banglish` for the roman mirror; `enterKeyBlocked` was set while the popup was open so the newline is suppressed. If no row: pass through |
| **Esc** | `initialize(True, presed_=True)` + `initThread_signal.emit()`. The already-injected Bangla **stays in the document**; only the composition buffer is dropped |
| **Space** | see §1.3: optional auto-commit of the selected row, then buffer reset, then the space itself is typed by the OS |
| **F1…F12** | `tempoComplition(item[n-1].text)` when the popup is visible and `using_functionKeys` |

`selectPreviousWord` / `selectNextWord` (L6764 / L6779) move the current row of
`contextClass.listWidget` when the context menu is open, otherwise of
`listClass.listWidget`. Previous wraps backwards; Next clamps at the last row and
jumps to row 0/1 depending on whether the buffer is empty (`wordSofar in ('', ' ')`)
— see the Down row above. Neither is a pure modulo.

`tempoComplition(selectedText, backSpaceCallingFromOwnReturn=False)` (L5680)
records the choice, derives `reversed_english_word` (the Bangla→roman reverse map,
either from `secondDicPKL.get_values_by_word(word)` picking `max(vals, key=len)` or

`english_word_so_far_histo[-1]` so later keys extend the *roman* buffer of the
chosen word, then calls `completeRestOfTheWord(selectedText, stopListener=True)`.

`completeRestOfTheWord` (L6483) is the same prune-and-retype primitive as
`convertToLayout`, plus caret gymnastics:

## 10. Inferred algorithm (compact)

```
on keydown(k):
    if bypass_call or k in pressed_keys (auto-repeat): return
    match k:
      Esc      -> reset_composition()                      # document untouched
      Left/Right -> re-anchor composition to caret word
      Space    -> maybe_accept_selected(); translate(' '); reset_composition()
      Up/Down/Tab -> row ± 1; preview(row)                 # document rewritten
      Enter    -> if row selected: accept(row) else passthrough
      printable -> compose(k)

compose(k):
    roman += k
    bangla_new = translate(roman)                    # whole word, native table
    bangla_old = rendered
    n          = len(bangla_old) - LCP(bangla_old, bangla_new)     # codepoints
    rendered   = bangla_new
    if n == 0 and bangla_new == bangla_old: return
    for i in 1..n: tap(Backspace)
    write(bangla_new[LCP:])
    arm_popup_timer(50 ms)

backspace():
    if buffer_empty and previous_word_restorable: restore_previous_word()
    roman = roman[:-1]
    compose(delta='')
```

## 12. Recommended state machine for Okkhor 0.10

Design goal: same *feel* (live Bengali while typing roman), none of the legacy
structural weaknesses (document mutation per key, codepoint-level diffs,
1-backspace assumptions, no anchor verification).

### 12.1 Principle

Keep exactly one source of truth — the **roman buffer** — and one derived string —
the **committed render**. Never diff against what the *user typed*; diff against
what *we last wrote*.

### 12.2 State

```rust
struct Composition {
    // identity of the edit site
    target: TargetId,            // hwnd + focused control signature + field kind
    anchor: Anchor,              // caret offset we believe we own + 16-char context hash
    // content
    roman: SmallString,          // bounded, NFC, ≤ 64 chars
    rendered: SmallString,       // what is in the document now (UTF-16 units!)
    history: SmallVec<Snapshot>, // one entry per accepted key (for Backspace)
    selected_row: Option<u8>,
    candidates: SmallVec<Candidate>,
    generation: u64,             // bumped per key; stale jobs are dropped
    // policy
    state: Phase,                // Idle | Composing | Previewing | Committing | Suspended
    deadline: Instant,           // per-key inference deadline (3 ms budget)
}

enum Event {
    Key { vk: u16, ch: Option<char>, mods: Mods },
    Backspace, Space, Enter, Escape, Tab, ArrowUp, ArrowDown,
    FocusChanged, CaretMoved, MouseClick {..},
    PopupTimer, SuggestJobDone { generation: u64, cands: Vec<Candidate> },
    Pause, LayoutChanged, EncodingChanged, PasswordFieldDetected,
}
```

### 12.3 Transition table (per event, in order)

| Step | Rule |
| --- | --- |
| 1. Classify | printable only if `!ctrl && !alt && ch` and layout maps it; `Escape` never mutates text; `Space`/`Enter`/punctuation are commits |
| 2. Guard | `Suspended`, `PasswordFieldDetected`, secure desktop, elevated target, or `anchor` mismatch ⇒ **pass the key through untouched**, reset composition |
| 3. Buffer | `roman.push(ch)` (bounded), push snapshot, `generation += 1` |
| 4. Translate | cached transliteration, hard deadline 3 ms; on timeout keep the previous render and mark the word `provisional` |
| 5. Plan | `lcp = common_prefix(rendered_utf16, next_utf16)`; **clamp `lcp` to a grapheme-cluster boundary** (base + combining marks + ZWJ sequences) so a backspace never lands inside a cluster |
| 6. Edit | `erase = rendered.len - lcp` (UTF-16 units, not chars), `insert = next[lcp..]`. Emit **one atomic batch**: `erase × KEYEVENTF_KEYUP/DOWN(Backspace)` followed by per-character `KEYEVENTF_UNICODE`, all in a single `SendInput` call |
| 7. Verify | if `SendInput` inserted fewer characters than requested, mark the composition dirty and re-sync from the caret (read-back via UIA/EM_GETSEL) instead of guessing |
| 8. Publish | update `rendered`, `anchor.caret += insert.len - erase`, bump `generation` |
| 9. Rank | arm popup timer (60–80 ms). Ranking job runs on the worker, ≤ 3 ms, keyed by `generation` |
| 10. Fail safe | on any error: keep `rendered` unchanged, mark `needs_resync`, and let the next key start a fresh composition |

### 12.4 Per-event detail

- **Printable**: steps 3–9. `erase == 0 && insert == ""` ⇒ no injection at all
  (the legacy app sends nothing only when the strings are equal — Okkhor should
  also skip the redundant `SendInput`).
- **Backspace**: pop `roman` and `history`; **do not** inject a backspace
  directly — recompute `next` from the shorter buffer and run steps 5–9. If
  `roman` is empty and the setting allows, restore the previous word as a whole
  (one edit batch), never a raw backspace into the previous word.
- **Space / `।` / `,` / `.` / `?` / `!`**: commit — freeze the current render,
  clear `roman`, close the popup, emit `WordCommitted` (this is the only place a
  learning event should fire). Then let the punctuation itself pass through
  (Okkhor never re-types punctuation). Space-sensitive rule tables are handled by
  translating `roman + " "` *before* the commit decision, never by re-typing the
  space.
- **Enter**: if a candidate is selected and the popup is visible → accept it
  (one atomic replace, then swallow Enter only if the user asked for
  "Enter accepts"); otherwise pass through and commit.
- **Tab / Up / Down**: move `selected_row`; preview = steps 5–8 with
  `next = candidate.text`, keeping `roman` **unchanged** so typing one more
  letter returns to the typed path. Up/Down must wrap; Tab must not steal focus
  while the popup is open (swallow at the hook, re-emit on close).
- **Escape**: `Phase::Idle`, clear `roman`/`history`/popup. **Text stays** (this
  matches Kontho and is the least surprising).
- **Caret move / click / focus change**: if the caret leaves the anchor range,
  commit and go `Idle`. Never apply an edit computed for an old anchor.
- **Layout / encoding change, pause, password field**: reset immediately; drop the
  popup.
- **Timer**: popup timer is coalesced (last key wins); suggestion job results with
  a stale `generation` are discarded.

### 12.5 Erase/inject lengths — normative

1. `erase` and `insert` are measured in **UTF-16 code units**, because that is what
   `SendInput` and `EM_*`/UIA caret offsets use. Bengali astral characters do not
   exist in practice, but the surrogate pair rule must still be enforced.
2. `erase = len(rendered) - lcp`, `insert = next[lcp..]`. This reproduces Kontho's
   `smertCompletor` exactly for ASCII-safe inputs and is *stricter* for clusters.
3. The whole pair must be **atomic**. Kontho splits it: each erase is its own
   `kb.tap(Key.backspace)` and the suffix goes through a separate `keyboard.write`
   (with the listener stopped/restarted in between). That is a correctness hazard:
   a slow target can observe intermediate text, an autocorrect can fire between
   the erase and the insert, and a modal dialog can steal focus mid-sequence.
4. Never assume a fixed previous length of 1. (Kontho's
   `completeWordBySpace` path does exactly that and is wrong whenever the previous
   word was longer than one character.)

### 12.6 Failure cases to handle explicitly

| Case | Detection | Response |
| --- | --- | --- |
| Target edited itself (autocorrect, autocapitalise, smart quotes) | `anchor` context hash mismatch before an edit | abandon the composition, resync, do not inject |
| Caret moved by the user or by the app | caret offset ≠ expected | commit, `Idle` |
| Focus changed / popup opened in the target | focus event | commit, `Idle`, hide popup |
| Elevated window / UIPI | `SendInput` returns short | re-emit the raw ASCII key so no keystroke is lost, `Suspended` |
| Password field | field kind from UIA | no popup, no learning, characters inserted but nothing retained |
| IME enabled in the target | `WM_IME_*` / `ImmGetContext` | suspend, or force ASCII so the IME cannot compose twice |
| RTL / bidi field | UIA property | suspend (injection order is not caret order) |
| Grayscale of graphemes | `lcp` inside a cluster | extend `lcp` to the cluster boundary (extra typed characters, never a broken cluster) |
| Partial injection | `SendInput` count < requested | resync from caret; never patch by counting |
| Very long word | `roman.len > 64` | stop composing, commit, pass keys through |
| Undo | `Ctrl+Z` in target | composition state is stale ⇒ `Idle` + resync (legacy Kontho creates one undo step per keystroke) |

### 12.7 What to take from Kontho, and what not to

Take:
- roman buffer as the single source of truth, per-word, reset on commit;
- whole-word retranslation (never incremental rule state);
- **minimal diff** against the last render, not "erase everything, retype";
- popup coalescing on a ~60 ms timer, with a hard row cap and the raw roman string
  as row 0;
- Up/Down/Tab selection with live in-document preview;
- Backspace pops one roman character, not one Bangla character;
- Escape clears the buffer and leaves the text.

Do not take:
- writing into the document on every keystroke when a real TSF/IME composition
  (underlined preedit) is available — prefer composition first, document edits
  only as the fallback for non-TSF hosts;
- codepoint-level diffs without cluster clamping;
- separate `SendInput` batches for erase and insert;
- the `completeWordBySpace` single-backspace assumption;
- three independent key-capture mechanisms (pynput observer + boppreh blocker +
  AutoHotkey host) where one reviewed low-level hook suffices (AGENTS.md §4);
- ranking that reduces to `max(score)` with recents-only personalisation — 0.9's
  Smriti contract already specifies the signals Kontho lacks.

### 12.8 Acceptance tests for 0.10

1. Golden roman→Bangla→edit-plan table: for each of ~200 roman prefixes assert
   `(erase_utf16, insert_text)` equals the diff of consecutive renders, including
   conjunct formation and vowel-sign changes.
2. Backspace property test: `render(roman[:-1])` after one backspace equals the
   document content implied by the edit plan (no drift over 200 random edits).
3. Grapheme test: no plan ever has `lcp` between a base and its combining mark.
4. Atomicity test: a stub target that records every `SendInput` call must see one
   call per keystroke.
5. Anchor test: mutate the stub document between keys; the engine must refuse to
   edit and must resync.
6. Candidate test: popup ≤ `SuggestionRows` (default 8–10), row 0 = raw roman when
   it differs from row 1, stale generations discarded.
7. Latency: keystroke→edit ≤ 3 ms p99 in the daemon (excluding target app).

## 13. Compatibility notes (bugs in the reference, for the parity matrix)

1. `smertCompletor` diff is codepoint-based and can split clusters.
2. Erase and insert are not atomic (separate `SendInput`s, listener restarted
   between them).
3. `completeWordBySpace` sends exactly one backspace regardless of the previous
   word length.
4. Popup capped at `int(numOfWrdPrediction) * 1` = 10 rows by default; F-keys are
   blocked for the full list length even though only 10 can be shown.
5. Ranking collapses multi-source candidates with `max(score)` and has no
   frequency/acceptance model.
6. `wordSofar` is assigned *before* the injection, so a failed `SendInput` leaves
   the state believing text that is not there.
7. Three key-capture mechanisms run concurrently (pynput, boppreh, AHK).

These are recorded as compatibility issues, not as improvements to copy
(AGENTS.md §"Working with the legacy app").
